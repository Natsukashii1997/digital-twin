# 群学习报告：内容核对与排错

常浩质疑报告/卡片里的某条「总结和原文对不上」「这结论哪来的」时用。先拿产物对账，再下结论；不要凭印象辩解，也不要先认错。

## 产物在哪

目录 `~/Library/Application Support/DigitalTwin/groupdigest/`（可被 `DT_GD_DIR` 覆盖），按统计日 `<YYYY-MM-DD>.*`：

| 文件 | 是什么 | 用来查 |
|---|---|---|
| `material.json` | 取数结果：`items`（群消息/X 卡片，编号 M1…）、`sources`（S1…，外链正文）、`coverage`（没抓到什么） | 原文真相 |
| `query.md` / `reply1.md` | 发给模型的提示 / 模型原始回复 | 模型写了什么、引用了哪个编号 |
| `report.md` | 完整报告 | 总结段落和引用 |
| `card-fields.json` / `card.sent.json` | 卡片字段 / 实际发出的卡片 JSON | 常浩看到的样子（折叠面板、原地址） |

截图里的文字先定位到哪一天：卡片标题/总结是模型改写过的，整句 grep 常落空，改用作者名、产品名等短关键词在各天 `card.sent.json` 里搜（`grep -l 作者名 *`），命中后再确认那一天。

## 核对顺序

1. 在 `material.json` 的 `items` 里找截图中出处编号对应的条目，读 `text` 全文——不只看 `gist`。
2. 在 `report.md` 里找那段总结，逐点对原文。
3. 在 `card.sent.json` 里递归找 `collapsible_panel`，看面板实际放了什么原文。
4. 分开报告三层：总结对不对原文、面板原文对不对总结、哪一步生成的（取数 / 模型写稿 / 脚本拼卡片）。

## 已知陷阱：一张 X 卡片里有多条帖子

- X 卡片常是「N 条新帖」，`text` 里用 `—— **k/N** ·` 分段；`gist` 只是**第 1 条**的摘要。
- 分段标题两种写法：中文博主是 `▶ k/N · 原文 · 展开`（只有 `**原文**`），英文博主是 `▶ k/N · 原文与译文 · 展开`（`**中文**` + `**Original**`）；只认后一种的代码会把中文帖全部漏掉。
- 引用只到卡片级（M1），没到帖子级；`groupdigest.py` 的 `original_md()` 找不到「原文与译文」段（中文帖没有译文段）时退回用 `gist`，于是总结讲第 2 条、面板放第 1 条，看起来「对不上」。有「原文与译文」段的卡片也只取第一段。
- 排查时先统计当天多帖卡片数，判断影响面：`re.search(r'—— \*\*2/', item['text'])`。
- 正确修法方向：帖子级编号（如 M1.2）→ 写稿引用到帖子 → 面板按编号取原文；对不上时宁可不放面板。改脚本属 digital-twin 工程改动，走 workshop 派单，不在会话里直接改。

## 回复常浩

先一句结论（哪层错了、是不是他看到的那段总结错），再给原文引文作证据、根因（文件+行号）、影响范围（几张卡片、哪几天），最后给修法并问要不要派单。
