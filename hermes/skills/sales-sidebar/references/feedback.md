# 销售 AI 侧边栏 · 需求反馈（每天 18:00，亚古兽）

常浩 2026-11-19 定：每天 18:00 把测试反馈群里的新反馈整理成《YYYY-MM-DD 需求反馈》，**先私发常浩确认**；他回「发群」才用他本人身份发到群里。版式由脚本固定（2026-11-13 定稿、11-17 补标题后空行、11-18 补「旧的每期复核」），你只写内容 JSON，不自己拼飞书消息。

脚本：`python3 ~/.hermes/profiles/agumon/scripts/sidebar_reports.py feedback <status|render|send|group>`（下文简称 `sr`）。

## 一、取数

1. `sr status`：拿上一期（早于今天）的 `read_from`（取数截止时间）和 `carry`（上一期所有 ✴️ 待解决、⬆️ 待上线，带原标题和原话）。今天已经出过一版（`today_sent` 不为空）也照样从 `read_from` 读起、重新整理全天，发送时脚本会原地改今天那条。
2. 读群消息：`lark-cli im +chat-messages-list --as user --chat-id oc_32562463635b4b2ee03d1808c080d1b5 --start <read_from 转成 2026-11-18T18:41:00+08:00 这种写法> --order asc --page-all --format json`。周末也算。
3. **群里从 `read_from` 到现在没有任何新消息**：不出这一期，最终回复只写一句「今天测试反馈群没有新反馈，本期不出。」，到此结束。
4. 回复里带截图的，用 `lark-cli im +messages-resources-download` 下载下来看，确认截图说的是什么再归类。

## 二、归类（处理情况只认群里的回复，主要看卢文等开发同学；私下会议、开发同步录音里的说法不算）

- **✅ 已修复**：群里有人回复「已修复」或同义说法，并且核实过对应的是哪条反馈。
- **✴️ 待解决**：已知、没修好的问题。
- **⬆️ 待上线**：新需求、已表态会做或即将上线的。
- **上一期的 ✴️ / ⬆️ 每期都要逐条复核，不能因为本期没进展就省掉**：
  - ✴️ 群里确认修好了 → 改列 ✅，原话照旧；没确认 → 原标题、原话照旧继续列 ✴️。
  - ⬆️ 群里没确认上线 → 原标题、原话照旧继续列 ⬆️。**确认上线了怎么列，常浩还没定**：遇到时不要自己定，在私聊里先问他（脚本也会拦下）。
- 顺序：✅ → ✴️ → ⬆️；同一类型里，上期带过来的在前（按提出时间），本期新增的在后。
- 同一问题的多条原话合成一项（`quotes` 里多条）。原话可以截取关键句，但不改字。
- 新的 ✴️ / ⬆️ 标题：一句话概括问题或需求，必要时括号里补处理情况，如「试听时长填 1H 会被自动改成 0.5H（Windows 和安卓端出现，兼容性问题排查中）」。

## 三、写内容 JSON 并发送

存到 `~/Library/Application Support/DigitalTwin/sidebar/drafts/feedback-YYYY-MM-DD.json`：

```json
{"date": "2026-11-19", "cutoff": "2026-11-19 18:00",
 "items": [
  {"type": "fixed", "quotes": [{"text": "原话", "name": "练欣雅", "open_id": "ou_..."}]},
  {"type": "pending", "title": "问题概括", "quotes": [...]},
  {"type": "planned", "title": "需求概括", "quotes": [...]}]}
```

- `cutoff` 写这次读群消息读到的时间，下一期从这里接着读。
- `open_id` 用群消息里该条发送人的 ID（`sender.id`），不要按名字猜。
- 零宽空格、引用块、@、空行都由脚本加，你不要加。

然后 `sr send <上面的路径>`：
- 核对不过（退出码 2）就按提示改 JSON 再跑，最多改两轮；还不过，把问题原文发给常浩。
- 成功后脚本已经私发常浩、读回核对并存档；**最终回复只写 `[SILENT]`**（定时任务里），免得重复推送。

## 四、常浩回复之后（私聊里）

- 他要改某处：改那一期的 JSON 再 `sr send`，脚本会**原地改原消息**，不另发。
- 他回「发群」：`sr group --date YYYY-MM-DD`。脚本会核对被 @ 的人都在群里、用他本人身份发一次、读回 @。结果里 `mentions_ok` 为 false 时，把 `mentions_missing` 告诉他。用户身份发出的消息不能改，只发一次；发过群的那一期脚本也不再改私聊稿。
- 他回「先不发」：什么都不做。下一期照常从这期的 `cutoff` 接着读，这期的 ✴️ / ⬆️ 照常带过去。
