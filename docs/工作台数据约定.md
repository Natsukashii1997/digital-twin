# 工作台数据约定（2026-11-20 第一版；2026-11-24 第二版补执行、记录、沉淀三页）

这份文档把工作台设计稿 [docs/design/workbench.html](design/workbench.html) 八页里的每一块，和底座里真正记这项数据的脚本、文件对了一遍：数据该从哪来，现在接不接得上。以后做工作台的实现、改示例数据、排底座批次，都先查这里；底座脚本装上或改了存储位置，回来改对应那一行。

状态只用四个词：

- **能接**：真源已安装，现在有真数据。
- **等批次**：真源写好了或在做，但没安装、没开、没数据；写明等哪一批。
- **没有真源**：底座里没有任何东西记这项数据；写明缺什么。
- **只是设置**：这块不显示运行数据，显示的是规则或设置；写明规则存在哪。

怎么读这些表：

- 一块里有几样数据、来源不同的，拆成几行，各判各的。所以「区块数」是表格行数。
- 按钮和操作另列小表，状态写「能接 / 等批次 / 没有入口」；只在页面里跳转的写「不调底座」。
- 「秘书上线」指：批 0B 剩下的 4d、0B-5 做完，批 0E 搬家降权过了三类反向验收，常浩签代批清单并在私聊开秘书。
- 核对依据：AGENTS.md「结构」一节、CURRENT.md 主线「执行底座改为 fork agent-autoloop」、`hermes/install_hold.txt`、[docs/未闭环账本-规格.md](未闭环账本-规格.md)，加上 2026-11-20 17:15 前后在本机只读看的安装目录和数据目录。标「推断」的是没核到原文的。
- 批名照 11-20 路线调整（#266）之后的 CURRENT：批 5 已拆成 5a 未闭环账本（规格常浩已确认，实现没开工）和 5b 续接与恢复。
- 第二版（11-24）只新增执行、记录、沉淀三页（按 DECIDED 11-24 两节的定稿逐块对），核对依据是 11-24 12:30 前后在本机只读跑的 `ai_access.py status --json`、`actions.py --date 2026-11-23`、`DigitalTwin/proposals/digest.json`、`pf-dt-worker.status`，加 origin/main `f5cdedb` 的 CURRENT。前五页的行没有重核：11-20 之后 5a 账本已装（`DigitalTwin/openloop/ledger.json` 有数据）、中台搬进 dt-gate、门卫接通，前五页里写「等批次 5a」「未安装」的行有一部分已经过时，接实况前逐行重核。
- 这份文档只做对照，不评价设计，不提改版建议。
