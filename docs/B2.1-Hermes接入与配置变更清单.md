## 2. 最小部署计划

**改哪些源码和安装文件**：源码 `hermes/scripts/twin_state.py`（改）、`twin_identity.py`（新）、`twin_events.py`（新）、`dispatch.py`（改）；安装副本四个文件复制到 `~/.hermes/scripts/`（`ops/self_check.py` 每天 09:50 逐个比对，少一个就报“安装缺文件”）；本机配置新增 `owner_chat_id`。技能、SOUL、config.yaml、cron 本批**一个都不改**。

**开关默认值**：

| 开关 | 默认 | 含义 |
|---|---|---|
| `DT_STATE_NOTIFY` | 未设（关） | `dispatch.py` 写入后通知状态库 |
| 正式库文件 | 不存在 | 不存在时通知、对账都跳过，绝不自动建库 |
| `owner_chat_id` | 未配 | 未配时 `--by user` 一律拒绝 |
| `DT_STATE_DB` / `DT_DISPATCH` / `DT_OWNER_*` / `DT_LARK_CLI` | 未设（走默认路径与真 lark-cli） | 测试与应急用的覆盖 |

**正式启用顺序（每步常浩批准，可单独停在任一步）**：

1. 合并 PR（常浩说“合并”，按《工程流程》第 5 节）。
2. 安装四个脚本到 `~/.hermes/scripts/`，`cmp` 一致，`self_check.py` 即时跑一次静默。脚本不需重启网关。
3. 常浩在和 Hermes 的私聊里随便发一条消息，拿它的 message_id（从网关日志或 `lark-cli im +chat-messages-list --user-id <猛鬼兽 open_id> --as user` 取），`twin_identity.py setup-chat --message-id om_… ` 预览（它会用 bot 身份查会话 `chat_mode`，只有 `p2p` 才给预览；是群聊报 `NotAuthorized`，拿不到类型报 `ChatModeUnknown` 并给手工配置说明——此时**不要**手工把没法确认的会话写进去）→ `--write` 写 `owner_chat_id`（600，先写临时文件再原子替换）；`twin_identity.py verify --message-id om_…` 应 `ok: true`，输出不含 id 值。2026-10-29 只读探针已确认该接口对常浩 ↔ 猛鬼兽私聊返回 `chat_mode=p2p`（证据 `evidence/b2.1-rework-20261029/probe-chat.masked.json`）。
4. 探针 ②（常浩操作）：在飞书私聊让 Hermes 执行 `env | grep '^HERMES_SESSION_' | cut -d= -f1` 并只回变量名——确认工具子进程真的拿到 `HERMES_SESSION_MESSAGE_ID`；顺带确认 `.env` 里的变量是否传到子进程（让它再 `env | grep -c '^DT_'`）。
5. 正式库：`twin_state.py init` → `backup` → `reconcile --dispatch ~/.hermes/dispatch`（预期 15 单 created、3 个目录 ignored、0 冲突，和 T01 报告一致）→ 再 `reconcile` 应全 unchanged。
6. `.env` 加 `DT_STATE_NOTIFY=1`；下一张真实工单的 `new / run / pr / merge / clean` 每次写入后 `twin_state.py show <单号>` 能看到状态跟着变，`state-notify.log` 没有失败行。
7. B2.2 起：cron 对账、技能接入、主动提醒；B2.x：网关凭据、卡片确认。

**必须重启什么**：本批没有。以后改 Skills / SOUL 才 `launchctl kickstart -k gui/$(id -u)/ai.hermes.gateway`。

**如何验证飞书身份与授权**（装好后在隔离库上做，不碰正式库）：

