## 1. 托管是什么

**托管期间，猛鬼兽以常浩的身份替常浩回话、批准、合并；底线之外自己判断；每个决定记账；托管结束后汇报，常浩可以逐条推翻。**

- 「以常浩的身份」指**权威**：Claude / Codex 把猛鬼兽的话当成常浩本人的决定来执行。
- 底线 = 授权清单 D 档 + **一切撤不回的动作**。底线上的事托管期间不做，挂起到常浩回来。
- 拿不准就挂起，不硬判。挂起只是慢，判错要返工。
- 托管是一段**有时限的授权**，来源只能是常浩本人（飞书私聊亲口说、驿窗本机开关、或常浩签的托管策略文件里的时段）。

## 2. 一次托管决定的完整路径

```
Claude/Codex 会话这一轮结束并在等常浩（提问、wrap_up 待决、批准卡）
  └─ 驿窗：托管开着？→ 把「待决事项」原文 POST 给猛鬼兽（本机 webhook，HMAC）   纸飞机：会话 → 猛鬼兽
       └─ 猛鬼兽：custody 技能
            ① 读原文、项目 CURRENT、Vault 偏好
            ② 出结构化决定 {动作, 回复原文, 依据, 撤回方法}
            ③ 出口闸 custody_gate.py：策略判定，不过就改成「挂起」
            ④ 记账（twin-state Event + 原文文件）
       └─ 驿窗：校验「托管中 + 发件是猛鬼兽 + 账本里有这个决定号」→ 以常浩身份送进会话   纸飞机：猛鬼兽 → 会话
            └─ 会话照做；执行点钩子拦 D 档命令（第三道闸）
托管结束 → 飞书汇报卡（逐条带「推翻」）
```

## 3. 七问的回答

### 3.1 通道（驿窗改动，新做为主）

| 方向 | 做法 | 新做 / 复用 |
|---|---|---|
| 会话 → 猛鬼兽 | 驿窗加收件方 `hermes`，送达方式是 POST 到猛鬼兽本机 webhook 路由 `custody`（`hermes webhook subscribe`，带 HMAC、挂 `custody` 技能、`--script` 先做确定性预筛）。**不走飞书**：飞书是给人看的，消息体有长度和格式限制，也会吵到常浩 | 驿窗新做收件方；Hermes webhook 现成，但 `platforms` 里目前只开了飞书，要开 webhook 平台〔待实测，改 Hermes 配置属 D 档〕 |
| 触发 | 托管开着时，驿窗在三种时刻自动转交，不需要 agent 配合：① 完成钩子触发、这一轮最后回答在等常浩（提问、wrap_up 有 ask）；② 批准卡出现；③ agent 主动 `send_message` 给 `hermes` | ① ② 复用现有完成钩子、注意钩子和「取最后回答」；「这一轮是否在等人」的判定新做 |
| 猛鬼兽 → 会话 | 驿窗加一个**只给猛鬼兽用的发件口**（本机命令或本地接口，带本机令牌），由 Hermes 侧确定性脚本 `custody_reply.py` 调用，不让模型直接调。不复用 `send_message` 的会话识别：Hermes 不是驿窗认得的四家会话，硬塞进去要伪造 caller | 新做 |

转交给猛鬼兽的内容要**全文**：会话 id、项目目录、这一轮最后回答原文、wrap_up 的 ask 和按钮、批准卡的命令和理由。驿窗现在「只送原文、不转会话记录」的原则不变。

### 3.2 身份（驿窗改动，改已定行为，要先发改动确认）

- **以常浩身份提交**（Claude Code 用 `asUser: true`），让会话按本人指令执行。
- **只在托管开着时、只对猛鬼兽发件口发的消息**生效。现有全局开关 `agentMessagesAsUser` 不拿来用，建议托管期间保持关：开着就是所有 agent 互相说的话都变成常浩的话，没有任何闸。
- **推荐保留一行代发标记**（待拍板，见第 8 节）：消息末尾附 `〔托管·猛鬼兽代发 d-0012〕`。理由：会话会把这句话写进 CURRENT、交接、PR 描述，写成「常浩说」就是假记录；有决定号，事后推翻能精确找到是哪一句。标记不降低权威，会话仍以本人输入处理。

### 3.3 底线闸：三道，程序闸为主

| 闸 | 位置 | 拦什么 | 强度 |
|---|---|---|---|
| ① 出口闸 | Hermes 侧 `custody_gate.py`（确定性脚本，模型之后、发出之前） | 决定是结构化的：动作类型（回复 / 允许 / 拒绝 / 合并 / 开会话 / 挂起）+ 对象 + 原文。按托管策略判：D 档动作、L3、超上限、撤不回、回退模型做出的判断（deepseek-flash 时只许规则判）→ 一律改成挂起。原文再过一遍禁止词表（推 main、部署、删除、付款、对外发……） | 中：结构化部分可靠，自由文本只能尽力 |
| ② 送达闸 | 驿窗发件口 | 托管没开、发件不是猛鬼兽、决定号在账本里查不到、链超上限 → 拒收 | 强（确定性） |
| ③ 执行点闸 | 接收会话的 PreToolUse 钩子（全局装，读托管状态文件） | 托管期间直接拒绝：`git push` 到 main、`gh pr merge`（合并只能走猛鬼兽的 `merge_act.py`）、`launchctl` / 安装部署、`hermes config set`、写正式 Vault 路径、`rm -rf` 等 | **最强**：拦在真正动手的地方，不管消息是谁说的 |

第 ③ 道是关键：前两道只能管「话」，管不住会话把话理解成什么。Claude Code 钩子可行；Codex 要看它的规则机制能否做到同等拦截〔待实测〕，做不到的话 Codex 会话托管期间只接「回复」类决定、不接批准。

### 3.4 批准卡（驿窗改动，新做，排在后面）

- 托管期间批准卡也转猛鬼兽，回「允许 / 拒绝 / 挂起」三种，挂起 = 卡片留着等常浩。
- 批准是**命令级**的，适合规则判：只读命令、项目目录内的读写、跑测试 → 允许；第 3.3 节 ③ 那张表里的 → 拒绝；其余交模型，拿不准挂起。
- 优先级低：常浩的会话多数开着 bypass，批准卡本来就少。钩子等待时长上限〔待实测〕。

### 3.5 来回上限（驿窗改动）

- 猛鬼兽的决定**不算**常浩插话、不清零。算的话，两个会话加猛鬼兽能无限循环。
- 托管单独计数：每条链最多 20 次猛鬼兽决定，每次托管总共最多 60 次（数字可调，写在托管策略里）。到上限就停这条链，挂起，进汇报。
- 常浩真人插话照旧清零。

### 3.6 汇报与撤回（digital-twin 新做）

**原文从哪来**：猛鬼兽自己记，不依赖驿窗日志。每个决定一条 twin-state Event，原文（收到的待决事项 + 发出的回复）存 `~/Library/Application Support/DigitalTwin/custody/<托管号>/`，保留 90 天。

**汇报**：托管结束发飞书卡片，按项目分组，每条一行「会话 · 问了什么 · 我替你定了什么 · 依据 · 结果」，挂起的单列在最上面。08:00 个人项目日报（D22）引用这份汇报，不重复写。

**撤回分四级**，每个决定在记账时就写好属于哪一级：

| 级 | 适用 | 点「推翻」后做什么 |
|---|---|---|
| 记录 | 所有决定 | 标为被推翻，写一条规则补丁候选（同合并官的做法），以后同类按常浩的判断来 |
| 纠正 | 回复类（选了方案、答了问题） | 以常浩本人身份给那个会话发「撤回 d-0012：……」，由常浩补一句正确答案 |
| 回退 | 合并 | `merge_act.py` 开 revert PR；revert PR 的合并仍走卡片按钮，常浩点了才合 |
| 撤不回 | 已发生的外部副作用 | 不该出现：撤不回的动作托管期间一律挂起。真出现了就是闸漏了，按事故处理 |

推翻之后，基于那个决定接着做的工作不会自动消失，汇报里写明「推翻后还剩什么」。

### 3.7 开关形态（两边都改）

- **托管状态只有一处真源**：digital-twin 的 `custody.py on|off|status`，状态写在 `DigitalTwin/custody.json`，带开始时间、结束时间、来源、策略版本。
- **入口三个，都写到同一处**：
  - 飞书私聊说「托管」「托管到 8 点」「我回来了」（已核验通道）；
  - 驿窗侧栏开关（调 `custody.py`）；
  - 托管策略文件里的默认时段（例如每晚 23:30–08:00）。模板 [托管策略-模板.md](托管策略-模板.md)，签好的放 `DigitalTwin/custody/policy.md`；带有效期，到期前日报提醒续签，不自动续；常浩随时可改、可撤销。
- **驿窗只读状态、不自己判定**：侧栏显示托管标识；转交和代发的纸飞机在会话和猛鬼兽那一栏之间飞。纸飞机、侧栏样式按 P-08 出三版再定。
- **和「以我的身份发送」的关系：并存，不联动**。全局开关留给它原来的用途（常浩在场时 agent 互相传话），默认关；托管走自己的「猛鬼兽发件口」，两者互不影响。

## 4. 托管期间合并

- 合并只走 `merge_act.py`，会话里自己 `gh pr merge` 被第 ③ 道闸拦掉。
- 同时满足才合：合并官判「建议合并」、L0–L2、CI 通过、带 `--match-head-commit`、没超过当晚上限。其余挂起。
- 托管合并在 `agreement.csv` 里记 `owner=custody`，不计入影子一致率。

## 6. 分批

先打通一条最小闭环，再铺开：**一个项目里，Claude 会话停下问 → 驿窗转猛鬼兽 → 猛鬼兽按推荐回 → 以常浩身份送回 → 记账 → 汇报 → 推翻**。

| 批 | 仓库 | 内容 |
|---|---|---|
| 0 | digital-twin | 本稿定稿；授权清单 v1；ARCHITECTURE 修订；送 ChatGPT 思维评审（动授权基线，属 A 类） |
| 1 | digital-twin | `custody.py` 状态与入口（飞书、策略时段）；托管账本；汇报卡 + 「推翻」按钮（复用 merge-buttons 插件） |
| 2 | digital-twin | Hermes webhook 路由 + `custody` 技能 + `custody_gate.py` 出口闸 + `custody_reply.py` |
| 3 | agent-kit / 全局 | 执行点闸：Claude Code PreToolUse 钩子；Codex 同等能力实测 |
| 4 | postpane | 读托管状态、侧栏标识；收件方 `hermes`（完成钩子触发转交）；猛鬼兽发件口（以本人身份 + 代发标记 + 送达闸）；托管上限；纸飞机飞向猛鬼兽。改已定行为，先发改动确认 |
| 5 | digital-twin + postpane | 托管合并（第 4 节）；批准卡代答 |

批 1–3 和批 4 可以并行；最小闭环要批 1、2、3、4 都到位才能端到端跑。

## 7. 待实测

- Hermes webhook 平台开启方式、本机监听地址、响应时长。
- Claude Code 以 `asUser` 提交后，会话记录里能否区分；桌面版暂停的会话能否收。
- Codex 有没有和 PreToolUse 同等的执行点拦截。
- 批准卡钩子最长能等多久。
- 「这一轮是否在等常浩」的判定准确率（wrap_up 有 ask 好判；纯文字问句要规则 + 模型）。

## 8. 常浩的决定（2026-11-09，回复「按推荐定」）

1. **身份形式**：以本人身份提交，消息末尾附一行代发标记 `〔托管·猛鬼兽代发 d-编号〕`。
2. **托管期间合并**：按第 4 节放开（合并官建议合并 + L0–L2 + CI 通过 + `--match-head-commit` + 不超当晚上限），其余挂起。
3. **夜间默认托管**：由常浩签一份托管策略文件，每晚 23:30–08:00 默认托管；托管时段内 D23 夜间提案没回复，按推荐组合执行（仍受 3 单上限）；常浩随时可以说「今晚不托管」。

这三项是方向决定，不是授权本身：托管策略文件签署、授权清单 v1、ARCHITECTURE 修订生效之前，猛鬼兽不得按托管行事。
