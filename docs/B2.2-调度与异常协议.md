# B2.2 · 调度与异常协议（D2）

接口在 `hermes/scripts/twin_scheduler.py`；机制与理由见 [D1 设计](B2.2-调度与恢复机制设计.md)。所有命令行最后输出一行 JSON（`ok / msg` + 本命令字段），`report --quiet` 没有新情况时不输出。

## 1. 调度决策（`decide` / `plan`）

每个未收尾（不是 completed / canceled）的任务一条：

```json
{"task_id": "T…", "goal_id": "G…", "title": "…", "decision": "dispatch|hold|skip|unsafe",
 "reason": "<原因码>", "why": "<中文说明>", "evidence": {…}, "next_action": "<下一步>"}
```

返回 `{ledger, decisions, occupied, counts}`；不含当前时间，同一状态重复评估结果逐字相同。判定顺序（先命中先定）：

| 顺序 | 原因码 | decision | 条件 / evidence |
|---|---|---|---|
| 1 | `goal_not_authorized` | skip | 目标不是 authorized（`goal_status`） |
| 2 | `task_not_ready` | skip | 任务 observed |
| 3 | `claim_unsafe` / `claim_open` | unsafe / hold | 有未结预留（`sched_key / claim_state / order_no / lease_until / note`） |
| 4 | `queue_unsafe` | unsafe | B2.1 `queue()` 的 unsafe 桶（`unsafe` 原因、当前 Run） |
| 5 | `running` | skip | 任务 running（当前 Run、单号） |
| 6 | `in_review` | skip | 待验收（`verdict`） |
| 7 | `blocked_decision` / `blocked_external` / `deps_unmet` | skip | 对应阻塞（`blocked_kind / blocked_reason / depends_on`） |
| 7 | `retry_suggested` / `retry_exhausted` / `retry_repeated` / `blocked_technical` | skip | 技术阻塞的重试分级（第 5 节） |
| 8 | `deps_unmet` | skip | ready 但依赖没完成 |
| 9 | `retry_over_limit` | unsafe | ready 但重试次数超上限 |
| 10 | `no_executor` | skip | 负责方不是 claude / codex |
| 11 | `no_project` | skip | 目标没写项目（名册 id） |
| 12 | `ledger_unavailable` | hold | 台账 missing / unreadable |
| 13 | `slot_full_global` / `slot_full_project` | hold | 名额满（`slots`、`occupied`） |
| 14 | `eligible` | dispatch | evidence：`goal / project / tool / retries / depends_on / ledger / slots` |

`dispatch` 只表示“可以派”，不是已派；执行要走 `tick --execute`（第 2 节）。

## 2. 预留、开单、恢复

| 调用 | 作用 | 结果 |
|---|---|---|
| `claim(store, task_id, sched_key)` | 写事务里复核 + 预留 | `{"applied": true, "claim"}` 或 `{"applied": false, "reason", "evidence"}`（拒绝不写任何东西） |
| `tick(store, executor, limit=1)` | 决策 → 预留 → 开单 → 按键核对关联 | `{claimed, refused, linked, released, unsafe, pending}` |
| `reconcile_claim(store, key, dispatch_dir)` | 核对一个未结预留 | `result`：`linked / released / void / unsafe / wait / noop` + `why` |
| `recover_claims(store)` / 命令行 `recover` | 逐个核对 claimed / ordered 的预留（unsafe 留给常浩） | `{sched_key: 结果}`；有 unsafe 时命令行 `ok=false`、退出码 1 |

关联键 `sched_key`：`S<时间>-<任务>-<随机>`，dispatch 校验 `S[0-9A-Za-z._-]{1,96}`。写在 `order.json.sched_key` 和单目录 `sched_key` 文件里。手工派单没有这个字段。

预留状态与转换：`claimed → ordered / released / void / unsafe`；`ordered → linked / unsafe`；`unsafe → linked / released / void`（只有 `user`）。

命令行 `tick --execute --mode read|write` 还要环境变量 `DT_SCHED_ENABLE=1`，并且派单根目录必须是 `~/.hermes/dispatch`（dispatch.py 只认这里）；本批正式环境不启用。`tick` 只开单不开跑。

## 3. 生命体征（`observe`，只读）

每个活动 Run（状态库里 new / queued / running 的）和台账里 running 却不在状态库的单一条：

```json
{"run": "R…|null", "task_id": "T…|null", "order_no": "D…", "ledger_status": "running",
 "vital": "alive|suspect|lost|finished|not_started|unknown", "why": "…",
 "evidence": {"worker": "match|gone|unknown|missing|previous|mismatch", "dispatch": "match|gone|unknown",
              "receipt": true, "worker_pid": 123, "worker_pgid": 123, "heartbeat_age": 456},
 "cancel_requested": false}
```

判定见 D1 第 6 节。`heartbeat_age` 只是证据。

## 4. 取消（`cancel`）

处理 `queue()["cancel_pending"]`，每个 Run 一条：`{run, task_id, order_no, vital, why, evidence, action, advice[, result]}`。

| action | result | 含义 |
|---|---|---|
| `none` | — | 已结束，等对账结算 |
| `advice` | — / `identity_changed` | 只给建议：没开跑（人工 `dispatch.py clean`）、身份核对不了、不是独立进程组、命令行模式、发信号前复核身份变了 |
| `signal` | `stopped` / `still_running` | 已对身份全对上的车间进程组发 SIGTERM（只在隔离测试里）；停不下来不升级 SIGKILL |

事件（object = run）：`run.cancel_<result 或 action>`（幂等键 `run.cancel:<Run>:<action>:<result 或体征>:<车间 pid>`）、`run.cancel_signal`（幂等键 `run.cancel_signal:<Run>:<pid>:<启动时间>`，同一进程只发一次）。

## 5. 重试与异常分级

| 原因码 | 条件 | 建议 |
|---|---|---|
| `retry_suggested` | blocked(technical)、`retries` < 上限、失败类别 `timeout` / `worker_failed`、台账那张单已结束、上一次不是同一种失败 | `retry_task`，不早于 `evidence.not_before`；正式环境不自动执行 |
| `retry_exhausted` | 到上限 | 常浩定 |
| `retry_repeated` | 和上一次同类别、同 `worker_error` | 常浩看原因 |
| `blocked_technical` | 类别 `unknown` / `lost`，或台账那张单还在跑 / 查不到 | 人工看原因 |

`evidence.failure` 给出类别。decision / external / dependency 阻塞从不出重试建议。

## 6. 报告（`findings` / `report` / `ack`）

一条：`{level: "error"|"needs_user", kind: "task"|"run"|"cancel", object, reason, why, fingerprint[, next_action]}`。

| level | 收进来的情形 |
|---|---|
| `error` | decision 为 unsafe；体征 lost；车间已结束但 dispatch 已不在、台账停在 running |
| `needs_user` | blocked_decision、in_review、retry_suggested / retry_exhausted / retry_repeated；在跑单体征 suspect / unknown；取消建议 |

`report` 只返回没报过的（按指纹查 `sched.report:<指纹>` 事件），不标记；`ack(items)` 标记（幂等）。命令行 `report` 先输出、后标记；`--quiet` 时没有新情况不输出。

## 7. 审计事件（状态库 events）

| kind | object | 何时 |
|---|---|---|
| `sched.claim` | task | 预留成功（payload：sched_key、project、lease_until、owner） |
| `sched.ordered` / `sched.linked` / `sched.released` / `sched.void` / `sched.unsafe` | task | 预留状态变化（payload：from、to、note、order_no / run_id） |
| `run.start` / `run.link` | run | 关联时（沿用 B1；幂等键 `sched.link:<sched_key>`） |
| `run.cancel_*`、`run.cancel_signal` | run | 第 4 节 |
| `sched.report` | — | 报告已送达 |

所有输出与事件都不含飞书 open_id / chat_id（调度器不读这两项配置；端到端场景 8 用哨兵值验证过）。
