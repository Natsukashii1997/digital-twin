# ADR-014 托管模式：托管期间猛鬼兽以常浩身份决策

- **状态**：提议（随 issue #127 的 PR 合并后生效；生效只代表规则成立，不代表任何托管动作已放行，见「生效顺序」）
- **日期**：2026-11-09
- **决定人**：常浩（2026-11-09 对设计稿第 8 节三项回复「按推荐定」）
- **规格**：[`../../托管模式-设计.md`](../../托管模式-设计.md)
- **架构基线**：[`../ARCHITECTURE.md`](../ARCHITECTURE.md) 4.3、5.5、5.6、5.7
- **影响的授权**：常设授权清单 v0 → v1（新增「托管」一节）；《工程流程》第 8 节第 4 条（加托管合并例外）；PRD D23（托管时段内没回复按推荐执行）

## 背景

1. 常浩不在场时（夜里、开会），Claude / Codex 会话停下问常浩、等批准卡、等合并，事情就卡住到常浩回来。D23 夜间提案只解决「夜里开哪几单」，开出来的单在夜里遇到要决定的事仍然停。
2. 驿窗已有「智能体互发消息」和「以我的身份发送」（驿窗主干 `243bcc6`，说明见驿窗 `docs/design/智能体互发消息与以我的身份发送-功能说明-2026-11-09.md`）：能把话以常浩身份送进会话，但只有全局开关，没有任何程序闸，Hermes 也收不到消息。
3. 现行合并放权路径（ARCHITECTURE 5.5）要求合并官影子运行同类 20 次、一致率 ≥ 90%，并要求驿窗补齐送审包指纹与审核模式记录。2026-11-09 合并官统计：L0 4 次、L1 6 次（67%）、L2 13 次，均未达标；按这条路径，放权还要很久。

## 决定

1. **新增运行模式 `CUSTODY`（托管）**，与 `SUPERVISED`、`UNATTENDED` 并列。托管期间，猛鬼兽以常浩的身份替常浩回复、批准、合并；底线之外自己判断；每个决定记账；托管结束后汇报，常浩可以逐条推翻。
2. **授权来源不变**，只认常浩本人：飞书私聊亲口说（已核验通道）、驿窗本机开关、常浩签的托管策略文件里的时段。转述、日报、模型自报都不是来源。
3. **底线 = 常设授权清单 D 档 + 一切撤不回的动作**，托管期间一律挂起到常浩回来；拿不准也挂起。
4. **三道程序闸**：猛鬼兽出口闸（确定性脚本按策略判结构化决定）、驿窗送达闸（托管中 + 发件是猛鬼兽 + 账本有该决定号）、执行点闸（接收会话的 PreToolUse 钩子，托管期间拦 D 档命令和会话自行合并）。底线不靠模型自觉。
5. **身份形式**：以常浩本人身份提交，消息末尾附一行 `〔托管·猛鬼兽代发 d-编号〕`，保证项目记录不把代发写成「常浩说」。
6. **托管合并**以「可回退 + 条件全满足」代替影子门槛：合并官判「建议合并」、L0–L2、CI 通过、带 `--match-head-commit`、不超当晚上限，只经 `merge_act.py` 执行。托管合并单独记账（`owner=custody`），不计入影子一致率。5.5 原有的 `owner_approved_policy` 路径保留，两条路径互不替代。
7. **夜间默认托管**：常浩签一份托管策略文件，每晚 23:30–08:00 默认托管；托管时段内 D23 夜间提案没回复，按推荐组合执行（仍受 3 单上限）。
8. **撤回分四级**（记录 / 纠正 / 回退 / 撤不回），每个决定记账时写好属于哪一级；合并的回退是开 revert PR，revert PR 的合并仍由常浩点卡片。

## 理由

- 常浩要的是「不在场时事情不停」，而不是「更快放权」。托管把放权限定在一段有时限、可随时收回、事后逐条可推翻的窗口里，风险比按动作类别永久放权小。
- 「撤不回就不做」把托管的最坏结果限制在「可回退的错误」，事后推翻才有意义。
- 底线放在程序闸，尤其是执行点闸，不依赖接收会话是否分得清谁在说话。

## 代价与风险

| 风险 | 对策 |
|---|---|
| 托管合并绕过影子门槛，免费版私有仓库没有远端分支保护，合并后只能事后回退 | 只放 L0–L2 + CI 通过 + 合并官建议合并；当晚上限；汇报逐条可推翻；revert 走卡片 |
| 自由文本回复里夹带越界指令，出口闸只能尽力识别 | 执行点闸拦在真正动手处；出口闸有禁止词表；拿不准挂起 |
| Codex 可能没有与 PreToolUse 同等的执行点拦截 | 实测前，Codex 会话托管期间只接「回复」类决定、不接批准 |
| 猛鬼兽回退到 deepseek-flash 时判断变差 | 回退期间只许规则判，需要模型判断的一律挂起 |
| 同一 macOS 用户下的恶意本地进程可伪造托管状态或调用发件口 | 沿用 5.2a 威胁模型边界：不防本地恶意进程；发件口要本机令牌，降低误调用 |
| 推翻后，基于被推翻决定接着做的工作不会自动消失 | 汇报里写明「推翻后还剩什么」 |
| 托管链在没人插话时无限循环 | 猛鬼兽决定不清零来回计数；每链 20 次、每次托管 60 次上限，到上限挂起 |

## 迁移与回退

- **生效顺序**：本 ADR 合并 → 常设授权清单 v1 同 PR 生效 → 批 1–5 落地并逐批验收（落地工单按 L3）→ 常浩签托管策略文件 → 托管才真正可用。任一前置没完成，猛鬼兽不按托管行事。
- **即时停用**：常浩在飞书说「我回来了」或「停止托管」，或在驿窗关开关，`custody.py off` 立即生效；进行中的决定按挂起处理。
- **彻底回退**：常浩撤销托管策略文件；驿窗发件口拒收一切；执行点闸保留（托管关闭时它不拦任何东西）。本 ADR 改为「已废止」，ARCHITECTURE 按 12.3 改版本，删去 `CUSTODY` 列。已经发生的托管合并按第 8 条逐条处理，不批量回退。
