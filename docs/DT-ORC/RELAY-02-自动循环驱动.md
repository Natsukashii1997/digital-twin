# RELAY-02 ORCA 自动循环驱动（#37，Part of #32）

## 1. 为什么做

常浩 10-31：「基于 ORCA 自动化推进，把整个数字分身项目推进结束」，不要每一步都让他确认。RELAY-01（PR #36）只解决了「送审包怎么进 ChatGPT、回执怎么回 Claude」这一段运输；把开发、审核、返修串成一个不需要人值守的循环，是本批的事。

## 2. 流程

```
relay_loop.py run
  ├─ 把任务说明交给 ORCA 终端里的 Claude（同一条只交一次）
  ├─ 等 round-N.ready（Claude 写完送审包后最后创建；驱动不猜送审包写没写完）
  ├─ 送审（RELAY-01）：第 1 轮在项目首页开新会话，之后固定在该会话
  │     发送前 relay 自己核对：指定会话、聊天模式、思考强度「高」（不是就调高并回读）
  ├─ PASS → 飞书私聊通知常浩「等合并闸门」，退出 0
  ├─ NEEDS_HUMAN → 通知，退出 20
  ├─ REWORK → 回执交回 Claude 返修，等下一轮 ready；返修超过 2 轮（D3-5）→ 通知，退出 20
  └─ 任何出错 → 通知，退出 2；排除后重跑同一命令即续跑
```

运行目录里的文件、续跑规则见 `orca/relay_loop.py` 开头的说明。续跑时：已有回执的轮次直接读回执；送审包有发送标记（上次发送结果不明）的，到标记记下的会话里 collect，不重发；交给 Claude 的消息、飞书通知都按键只发一次（飞书侧另带幂等键）。

## 3. 通知

用猛鬼兽 bot 身份私聊常浩（`lark-cli im +messages-send --as bot --user-id <owner_open_id>`），open_id 从本机受控文件读，不进仓库。只发任务标题、轮次、结论和回执路径，不带回执正文。

## 4. 闸门（哪些仍要常浩点头）

驱动本身不合并、不安装、不改正式配置；交给 Claude 的消息里也明确写了这些不许做。PASS 之后停在「等合并闸门」。常浩 10-31 的要求是自动推进；具体哪些闸门保留（合并、正式安装部署、对外发送、NEEDS_HUMAN），以常浩的答复为准，结论记在 CURRENT。

## 5. 实测发现

- **ORCA 终端里的 Claude 要带代理启动**：Orca 终端里没有代理环境变量，`claude` 直连 Anthropic 被拒（`API Error: 403 Request not allowed`）；系统代理是 `127.0.0.1:8086`，但命令行程序不会自动使用。另外 Orca 用 shell 函数包装了 `claude`，把 `CLAUDE_CONFIG_DIR` 指到它自己管理的配置目录。启动命令统一为：
  `HTTPS_PROXY=http://127.0.0.1:8086 HTTP_PROXY=http://127.0.0.1:8086 command claude --permission-mode auto`（用默认登录，auto 模式）。首次在新目录启动会问是否信任该文件夹。
- **新会话先用临时编号**：在项目首页开新会话，发送后地址先是 `/c/local-chatgpt%3A…`，服务器分配真实编号后才换掉。RELAY-01 曾把临时编号当成会话，真实编号出现时报「会话变了」（送审包其实已发出）。已修：`conversation()` 把临时编号当作还没进入会话。
- **续跑收回执要等**：思考强度「高」时回复要几分钟；续跑走 collect 时，驱动在送审超时内反复收，不再看一眼就报错。
- **思考强度读数会变**：切到一个会话后，强度按钮先显示默认的「中」，约 1 秒后才换成该会话记住的值。所以 relay 要连续两次读数一致才判断；先读到瞬时的「高」、随后稳定在「中」，也会调高。
- `orca terminal send --enter` 遇到 Orca 认为 Claude 界面上有确认提示时会拒收（`agent_prompt_blocked`）；原样字节（不带 `--enter`，用 `\r`）不受影响。

## 6. 已知限制

- 驱动由一个进程跑完一个任务；多个任务排队、任务完成后自动接下一个，是下一批的事。
- 驱动只看就绪文件，不看 Claude 有没有真的开始干活：任务交出去后 Claude 报错停住（如上面的 403），驱动会等到超时才报。
- ChatGPT 的 GitHub 连接器读不到 digital-twin（404），审核方只能核对送审包里的 diff 和证据，每轮都会登记「提交真实性未独立核验」。需要常浩在 ChatGPT 里给连接器开通这个仓库。
- 共用浏览器标签在驱动运行期间不能人工操作（RELAY-01 已记）。

## 7. 首次真实试运行（digital-twin #38，2026-10-31）

任务：`Marker.bind()` 改为原子写（RELAY-01 技术债 P2-01-R3）。结果：Claude 开发并开 [PR #39](https://github.com/Natsukashii1997/digital-twin/pull/39) → 第 1 轮 REWORK（P1 是 GitHub 连接器 404、证据不能独立核实，不是代码缺陷）→ 驱动自动把回执交回 Claude → Claude 补齐 issue 原文和提交信息 → 第 2 轮 PASS → 飞书通知常浩，停在合并闸门。Claude 开发约 2 分钟，返修约 1.5 分钟，每轮审核约 1 分钟。

中途三次人工介入，都已修到代码或文档里：Orca 终端的 Claude 403（改带代理启动，见第 5 节）；新会话临时编号（已修 relay）；续跑 collect 太早（已改为反复等）。证据：`evidence/relay02-20261031/trial-issue38.log`（原样，含人工介入记录）与运行目录副本 `run-issue38/`。
