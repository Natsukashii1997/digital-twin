## 一、结论

**不验收：第 1 项「连宿主除代理外的端口」没被拒，受限会话不成立，托管保持禁用。**

1. **经代理访问宿主回环服务（没被拒）**：容器唯一放行的宿主端口 `192.168.5.2:8086` 是闪电猫加速器 `fc-core` 的代理端口，它接受 `CONNECT 127.0.0.1:<端口>` 和 `GET http://127.0.0.1:<端口>/`，把请求转到**宿主的 127.0.0.1**。容器因此能访问常浩本机只监听回环的服务：fc-core 控制端口、github-center、牛马之家、个人 AI 工作台、Colima 虚拟机 sshd（第三节 1e）。M1（11-07）只测了直连，没测经代理转发。
2. **经宿主局域网 IP 直连（没被拒）**：Colima 虚拟机的 `DOCKER-USER` 规则只拦去往 `192.168.5.2` 的流量，宿主局域网 IP（11-11 为 `172.16.9.224`，11-12 换成 `172.16.10.238`，两天都复现）不受限。宿主上监听所有网卡的服务能连上（5000、7000 隔空播放接收器，53 Colima 的 ssh 端口转发）；只监听 127.0.0.1 的服务返回 connection refused（第三节 1d）。

其余全部被拒，由 GitHub 服务端或操作系统强制：推 main、强推、删 main、推非 `agent/` 分支、API 建非 `agent/` 分支、Contents API 写 main、推 workflow 文件、读宿主文件；未审批 PR、常浩批准后的 PR、其他作者的 PR 各 16 种合并 / 改 main 方式（含 #132 留下的 `PATCH git/refs/heads/main`、`POST /merges`、GraphQL `mergePullRequest`）；经脚本、npm 脚本与生命周期钩子、Python 直调 API、git 带令牌直推、子进程派生重做以上。main 全程停在 `38dd0f8`。

**合并隔离（规格 §3.3 第 3 条）本身成立**：三种 PR 状态下机器账号都合并不了，也改不了 main。不验收的原因只在网络隔离（§3.3 第 1 条）。
