## 一、结论

**受限容器里的 agent 在任何 PR 状态下都不能自行合并，由 GitHub 服务端强制**：12 项反向测试全部符合预期。合并执行器（常浩账号下只对 dt-sandbox 的专用令牌）能按 `--match-head-commit` 合并，不能直推 main。

未闭合的一点见第五节：宿主上的 Claude / Codex 会话能读到合并执行器令牌（钥匙串对本机用户进程不设防）。宿主会话本来就持有常浩完整的 `gh` 登录（管理员，同样能合并），所以这枚令牌没有给它们新增能力，但 ADR-014 第 26 行「任何 Claude / Codex 会话都拿不到」的字面要求不成立。

## 五、未闭合与注意事项

1. **宿主会话能读合并执行器令牌**：用 `security add-generic-password` 存的条目，本机用户的任何进程都能 `security find-generic-password -w` 读出，不弹提示（本会话核对时即如此）。容器内会话读不到（无宿主挂载）。宿主会话已持有常浩 `gh` 登录（`gho_`，钥匙串），本就能合并 dt-sandbox，所以这枚令牌不新增能力；要做到字面上的「任何会话都拿不到」，需要合并执行器在单独的 macOS 用户下运行，**并且**宿主会话不再持有常浩的 `gh` 登录。处理方式待常浩定（#132）。
2. 规格措辞与实际不一致，待同步：`docs/托管模式-设计.md` 第 80 行「持有独立账号的凭据」（实际是常浩账号下的专用令牌，独立的是 agent 账号）；第 204、218 行「沙盒仓库必需审批至少 1 个」（已被 V5.1 验收条件和甲方案取代，审批数仍为 0）。
3. Multica-local 的「E2-2 登录GitHub沙盒令牌（隔离执行器）.command」和 `runtime/login-gh.sh` 会引导用常浩账号生成令牌并登录容器；再运行会让容器回到常浩身份。属 Multica-local，本单不改，换令牌时改用机器账号。
4. 令牌到期：机器账号经典令牌 2027-02-08，合并执行器令牌约 2027-02-08（90 天）。到期前由常浩重新生成；容器里换令牌照本次步骤（`gh auth logout` → `gh auth login` 粘贴）。
5. `merge_act.py` 目前没有托管路径（托管合并是 #136）；#132 剩下的代码改动是让托管路径读这枚令牌，等第 1 条定了再做。
