# 0E-4 放开受信发布：常浩照抄的命令清单

\#195 批 0E-4（PR #319）。做完以后，dt-gate 里的受信发布（`autoloop_publish.py`）用机器账号 shanhao1997 的令牌，真推 dt-sandbox 的 `<执行方>/<单号>` 分支、真开 PR；合并 PR 仍由你点。

AI 不跑这些命令、不看令牌：令牌只在你的终端里粘贴一次，由脚本进程转交给 dt-gate，屏幕上不显示。每一步都写了「怎样算过」，不过就停在那一步，把输出贴回 Claude 会话。

```bash
GATE="/Library/Application Support/DigitalTwin/gate/bin/dt-gate-hub"
```

（每开一个新终端窗口先跑这一行。下面的命令都用它。）

## 开始前（三件都要是「是」）

1. **#320（代次边界）和 #319（本批）都已合并**。DECIDED 11-22 定了：#320 合并之前不放开真发布。脚本也会核：副本里的受信发布没有代次边界，第 5 步直接拒绝。
2. **中台已搬进 dt-gate**（0E-2），`sudo "$GATE" status` 里三个服务都在跑。
3. **dt-gate 的恢复闸开着**：`sudo "$GATE" run autoloop_recovery status` 显示开着（没开的话先按 0E-2 清单「以后要用到的」锁定中台版本、对账）。

## 第 1 步：用 shanhao1997 建经典令牌（GitHub 网页，你亲手做）

浏览器登录 **shanhao1997**（不是你自己的账号：你的令牌是管理员的，能推 main，脚本会拒收）→ 右上角头像 → Settings → Developer settings → Personal access tokens → **Tokens (classic)** → Generate new token (classic)：

- Note：`dt-gate 受信发布`
- Expiration：90 days（到期前重建，再跑一次第 3 步）
- 权限只勾 **public_repo**，别的一个都不勾

**怎样算过**：页面上出现一串 `ghp_` 开头的令牌（只显示这一次）。点复制，先别关页面，第 3 步要粘贴。

## 第 2 步：把 gh 一起装进副本（主账号终端）

先把仓库主目录拉到合并后的 main，查出完整提交号：

```bash
cd ~/Documents/ChatGPT/个人/work/digital-twin && git checkout main && git pull && git rev-parse HEAD
```

把上面打出的 40 位提交号填进下面 `--repo-commit`（引擎提交不变，仍是 dt-gate 现在锁定的 `abc8d41…`；跑之前用 `sudo "$GATE" status` 第一行核一下引擎前 12 位）：

```bash
sudo "$GATE" stage --engine-repo ~/Documents/ChatGPT/个人/work/agent-autoloop --engine-commit abc8d41efdc97efe4c25bac8376460424baec726 --repo ~/Documents/ChatGPT/个人/work/digital-twin --repo-commit <40 位提交号> --node ~/.nvm/versions/node/v24.16.0/bin/node --gh /opt/homebrew/bin/gh
```

**怎样算过**：最后两行是「副本好了：引擎 abc8d41efdc9、本仓库 <你填的前 12 位>、node v24.16.0、gh 2.90.0（SHA-256 …）」和「以后的命令用：…」，没有 `[停下]`。

再把服务换到新副本：

```bash
sudo "$GATE" update --confirm
```

**怎样算过**：没有 `[停下]`；接着跑 `sudo "$GATE" status`，第一行是新的本仓库提交号，第二行「gh 副本：2.90.0」，三个服务都「在跑」，中台健康检查 HTTP 200。

## 第 3 步：放令牌

```bash
sudo "$GATE" put-publish-token --confirm
```

提示「粘贴 shanhao1997 的经典令牌…」时，粘贴第 1 步复制的令牌、回车（屏幕上不显示，正常）。

**怎样算过**：
- 第 1 行「令牌已以 dt-gate 身份写进 /Users/dt-gate/.dt/github-publish.token（600，内容不显示）」；
- 第 2 行之后的一行 JSON 里：`"ok": true`、`"login": "shanhao1997"`、`"admin": false`、`"push": true`、`"scopes": ["public_repo"]`；
- 最后一行「令牌核对通过」。

**不过时**：看 `reason`。「多勾了权限」→ 回第 1 步删掉这个令牌、重建只勾 public_repo 的，再跑本步；「不是登记的账号」→ 用错账号建的，同样重建；「gh 副本」相关 → 第 2 步没带 `--gh` 或没 `update`。令牌放进去了但核对不过时不要往下走。

核对通过后，回 GitHub 页面关掉令牌显示（令牌只存在 dt-gate 里，别处不留）。

## 第 4 步：联网自检

```bash
sudo "$GATE" run gate_github doctor --repo dt-sandbox --online
```

**怎样算过**：每一行都是 `[通过]`，最后一行「自检全过」。其中：
- 「运行账号是 dt-gate」「发布令牌文件」「gh 副本只有 root 能改」都通过；
- 「真发布开关」这一行是「关着（没有开关文件）」——这时还没打开，是对的；
- 「代理」一行是「不走代理，直连 github.com」；
- 「联网（直连）：令牌身份和权限」是「shanhao1997，push=true、admin=false」；
- 「联网（直连）：不带令牌读得到 main」打出 main 的前 12 位；
- 「交接目录读得到」「凭证库（只读）」「中台库（只读）」都通过。

有 `[不过]` 就停下，把整段输出贴回 Claude 会话。

## 第 5 步：打开真发布

```bash
sudo "$GATE" publish on --confirm
```

脚本会先核副本里有 #320 的代次边界、有 gh 副本，再以 dt-gate 身份把第 4 步的联网自检重跑一遍，全过才写开关文件，写完以 dt-gate 身份回读。

**怎样算过**：
- 「1. 以 dt-gate 身份自检…」下面每行 `[通过]`、「自检全过」；
- 「2. 写好开关文件 /Library/Application Support/DigitalTwin/gate/publish.json：放开 dt-sandbox，直连」；
- 「3. 以 dt-gate 身份回读：开关开着。真发布已打开…」。

再跑一次 `sudo "$GATE" status`：有一行「真发布开关：开着，放开 dt-sandbox，直连，nat 于 <时间>」。

到这里就放开了。之后哪一单要发布、怎么核对，由协调会话一单一单安排，第一次真发布时你在场看着。

## 要关掉的时候（正常不用跑，不是上面步骤的一部分）

关真发布永远允许，不用 `--confirm`：在终端里输入 `sudo "$GATE" publish off`。它只删开关文件；之后受信发布不推、不开 PR，已经推出去的分支和开着的 PR 不动，出口账本对账照常（直连）。令牌留在 dt-gate 里，下次打开不用重放；要作废令牌，去 shanhao1997 的 GitHub 页面删掉它。

## 剩余风险（写明，不在本批解决）

- 令牌在 dt-gate 进程的环境变量里，同一账号的进程看得到（ADR-015 的隔离单位是账号）。
- gh 副本是第 2 步那一刻从主账号的 Homebrew 复制的，Homebrew 的 gh 没有官方签名可核：信任「装的那一刻主账号可信」，所以第 2 步要在刚 pull 下来的 main 上跑。
- 经典令牌勾 public_repo，理论上能写 shanhao1997 有写权限的所有公开仓库：现在只有 dt-sandbox；不要再把这个账号加成别的仓库的协作者。
- 令牌 90 天到期；到期后受信发布会报「令牌身份…失败」、不推不开，重建令牌再跑第 3、4 步即可（开关不用重开）。
