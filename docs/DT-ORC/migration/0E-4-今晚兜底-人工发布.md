# 0E-4 兜底：第一张真实派单由常浩人工发布

常浩 2026-11-22 定（`docs/DECIDED.md`「首单发布兜底」）：发布凭据（0E-4）当晚没审完时，第一张真实派单的「推分支、开 PR」由常浩在场核对后手动做一次；工人 dt-worker 仍然不碰 GitHub 写权限。

这份清单只靠已经合并、已经装好的东西（0C 的 `autoloop_publish.py scan`、0E-2 的入口 `dt-gate-hub`），不依赖 0E-4 的 PR。命令都由常浩在**主账号终端**里亲手跑；AI 不跑、不代推。

## 要核对的七样（都对才推）

| # | 核对什么 | 在第几步 |
|---|---|---|
| 1 | 单号、仓库、分支名对：分支正好是 `<执行方>/<单号>`，仓库是 dt-sandbox | 2 |
| 2 | 交接包的哈希和清单写的一致（包没被换过、没在半路更新） | 3 |
| 3 | 这张单的凭证现在有效，这一轮在中台里是正常结束的 | 4 |
| 4 | 包里只有本单这一个分支，头提交和清单一致 | 6、8 |
| 5 | 基线是 main 上的提交，头提交从基线长出来，中间没有合并提交 | 8 |
| 6 | 每一个提交都没碰高风险路径（`.github/`、`ops/`、`.plist`、`.env`、`.pem` / `.key` / `.p12`，文件名带 secret、credential、token、password） | 9 |
| 7 | 实际改动和任务单的五要素对得上，没有多做 | 9 |

任何一样不对：**停下，不推**，把那一步的输出发回 Claude 会话。第 10 步之前什么都没发出去，停在哪一步都不用收拾（最后把临时目录删掉即可）。

## 开始前

```bash
T=t-20261122-xxxxxx
```

```bash
W=~/dt-manual-publish/$T && mkdir -p "$W" && chmod 700 "$W"
```

```bash
GATE="/Library/Application Support/DigitalTwin/gate/bin/dt-gate-hub"
```

## 第 1 步：把交接包取出来

以 dt-worker 的身份读（不用 root 读：交接目录是工人能写的，里面要是被换成链接，root 会顺着读到别处）。

```bash
sudo -u dt-worker /bin/cat "/Users/dt-worker/dt-outbox/$T/handoff.json" > "$W/handoff.json"
```

```bash
sudo -u dt-worker /bin/cat "/Users/dt-worker/dt-outbox/$T/$T.bundle" > "$W/$T.bundle"
```

预期：两条都没有输出。报 `No such file` 就是交接包不在，停。

## 第 2 步：看清单

```bash
/usr/bin/python3 -m json.tool "$W/handoff.json"
```

预期：正好 12 项（schema、task_id、generation、executor、repo、branch、base、head、bundle、bundle_sha256、run、at）。逐项看：

- `task_id` 等于 `$T`；`repo` 是 `dt-sandbox`；
- `branch` 正好是 `<executor>/<task_id>`（例如 `claude/t-20261122-xxxxxx`），不是 main、不是别的名字；
- `bundle` 是 `<task_id>.bundle`。

把清单里的四个值记成变量（照抄，会自动从清单里取）：

```bash
B=$(/usr/bin/python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["branch"])' "$W/handoff.json"); BASE=$(/usr/bin/python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["base"])' "$W/handoff.json"); HEAD=$(/usr/bin/python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["head"])' "$W/handoff.json"); echo "分支 $B 基线 $BASE 头提交 $HEAD"
```

```bash
case "$B" in claude/$T|codex/$T) echo 分支名对 ;; *) echo "分支名不对：停" ;; esac
```

预期：`分支名对`。

## 第 3 步：核哈希

```bash
shasum -a 256 "$W/$T.bundle" | cut -d' ' -f1; /usr/bin/python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["bundle_sha256"])' "$W/handoff.json"
```

预期：两行一模一样。不一样可能是工人正在更新交接包：等一分钟从第 1 步重来，还不一样就停。

## 第 4 步：凭证有效、这一轮正常结束

```bash
sudo "$GATE" run autoloop_publish scan
```

预期：列表里 `task_id` 是这张单的那一项，`check` 写「可以发」，`generation`、`head`（前 12 位）和清单一致。写着「已撤销」「已冻结」「过期」之类就停。

```bash
sudo "$GATE" run agent-autoloop runs
```

预期：清单里 `run` 那个轮次号的状态是 `done`，最后一条消息**不是**以「停下了」开头。不是就停。

## 第 5 步：准备一个干净的 dt-sandbox 副本

```bash
git clone --quiet --bare https://github.com/Natsukashii1997/dt-sandbox.git "$W/repo.git" && git -C "$W/repo.git" rev-parse --short refs/heads/main
```

预期：打印 main 现在的短提交号。裸仓库没有工作区，后面不会检出、也不会运行交接包里的任何文件。

## 第 6 步：验包，看包里有什么

```bash
git -C "$W/repo.git" bundle verify "$W/$T.bundle"
```

预期：最后一行 `… is okay`。

```bash
git -C "$W/repo.git" bundle list-heads "$W/$T.bundle"; echo "应当只有一行：$HEAD refs/heads/$B"
```

预期：上面只有**一行**，和提示的那一行一模一样。多出别的分支、标签，或者提交号不同，停。

## 第 7 步：只取 Git 对象

```bash
git -C "$W/repo.git" -c core.hooksPath=/dev/null -c fetch.fsckObjects=true fetch --quiet --no-tags "$W/$T.bundle" "+refs/heads/$B:refs/dt-manual/$T"
```

预期：没有输出。取进来的东西放在 `refs/dt-manual/` 下面，不是分支，不会被顺手推出去。

## 第 8 步：头提交、基线、合并提交

```bash
[ "$(git -C "$W/repo.git" rev-parse "refs/dt-manual/$T")" = "$HEAD" ] && echo 头提交对 || echo "头提交不对：停"
```

```bash
git -C "$W/repo.git" merge-base --is-ancestor "$BASE" refs/heads/main && git -C "$W/repo.git" merge-base --is-ancestor "$BASE" "$HEAD" && echo 基线对 || echo "基线不对：停"
```

```bash
echo "合并提交数：$(git -C "$W/repo.git" rev-list --min-parents=2 "$BASE..$HEAD" | wc -l | tr -d ' ')（应当是 0）；提交数：$(git -C "$W/repo.git" rev-list "$BASE..$HEAD" | wc -l | tr -d ' ')"
```

预期：`头提交对`、`基线对`、合并提交数 0。

## 第 9 步：看改了什么（人看）

每个提交动了哪些文件（先加后删的也会列出来）：

```bash
git -C "$W/repo.git" log --no-renames --name-status --format='--- %h %an %s' "$BASE..$HEAD"
```

机器帮着找高风险路径（和自动发布用的是同一组规则）：

```bash
git -C "$W/repo.git" log --no-renames --name-only --format= "$BASE..$HEAD" | sort -u | grep -E '^\.github/|^ops/|\.plist$|(^|/)\.env|\.(pem|key|p12)$|secret|credential|token|password' && echo "碰到高风险路径：停" || echo 没碰高风险路径
```

预期：`没碰高风险路径`。

完整差异：

```bash
git -C "$W/repo.git" diff "$BASE" "$HEAD"
```

对照这张单的五要素（任务单在 `/Users/Shared/dt-gate/tasks/$T.md`）：改的文件、改的内容都在任务范围里，没有多做。拿不准就停下问。

## 第 10 步：推分支（从这一步起才有东西发出去）

用常浩自己的 GitHub 登录，只推这一个提交到这一个分支，不带 `--force`：

```bash
git -C "$W/repo.git" push https://github.com/Natsukashii1997/dt-sandbox.git "$HEAD:refs/heads/$B"
```

预期：`* [new branch]  <提交号> -> <分支名>`。报 `rejected`（远端已经有同名分支、内容不同）就停，不要加 `--force`。

## 和自动发布的差别（要知道的）

- **出口账本里没有这一笔**：人工发布不经 `autoloop_exits`，账本里看不到这次推分支和开 PR。「账本里看得到」这条验收，这一单要靠 PR 本身和这份清单的输出作证据。
- **PR 作者是常浩本人**，不是机器账号。
- **不重复**：以后自动发布同一张单时，远端分支已经是这个头提交就不再推；已有的 PR 目标是 main、来源是本仓库、头提交一致就沿用。
- 自动发布还核一样人工清单没法机械核的：交接包落到的那一轮，顺着中台里的事件能追到这张单**当前代次**的派单（`bind_run`）。人工这次由第 4 步的「凭证有效、轮次正常结束」加常浩在场看着这一单跑完来顶替。
