## 准备时做的加固

| 加固 | 做法 | 回读 |
|---|---|---|
| 容器访问宿主只放行代理 | Colima 虚拟机 `iptables` `DOCKER-USER` 链：去往宿主 `192.168.5.2` 只放行 TCP 8086，其余 DROP；写进 `~/.colima/multica/colima.yaml` 的 `provision` | 见下表第 2 行；重启后是否仍在见文末 |
| main 不可直推 | 分支保护：必须经 PR、`enforce_admins`、禁止强推和删除 | API 回读 `{pr:true, enforce_admins:true, force:false, del:false}` |
| 只能有 main 与 `agent/` 分支 | 仓库规则集 `only-main-and-agent-branches`：include `~ALL`，exclude `refs/heads/main`、`refs/heads/agent/**`，禁止 creation / update / deletion，无绕过者 | 见下表第 5 行 |
| GitHub 凭据只对沙盒仓库有效 | 常浩亲手生成 fine-grained 令牌，只选 dt-sandbox，Contents 与 Pull requests 读写 | 容器内 `gh api user/repos` 只列出 dt-sandbox |
| agent 不继承本机 MCP | 两个 agent 的 `mcp_config` 设为 `{"mcpServers":{}}`，daemon 以 `--strict-mcp-config` 拉起 | `agent get` 回读 |

## 结论（对照 5.2c）

- 第 1、2 条（受限执行身份、受限仓库凭据）：~~**成立**~~（已撤销，见上表第 2 行）。当时实测确认：容器没有挂载宿主目录，经 `192.168.5.2` 直连宿主非代理端口被拦；GitHub 写权限只限 dt-sandbox，且远端只接受 `agent/` 分支。但 #135（2026-11-11）证明容器能经宿主代理和宿主局域网 IP 访问宿主服务，原网络隔离结论已撤销；个人凭据是否完全隔离，也不能只凭文件系统测试确认。
- 第 3 条（权限矩阵）：任务令牌在**本工作区内**能指派、改状态、建 Wakeup，平台不拦；跨工作区被平台拒绝。按 5.2c 第 3 条，首跑放在只含沙盒项目的专用工作区「DT 沙盒」，越权只能波及沙盒。
- 5.3a 独立停机检查**尚未实现**：M2 首跑期间由常浩在场兜底，run-log 和晨报中如实标注；M5 无人值守夜跑前必须先实现。
- 据此，M2 有人值守首跑的执行环境准入条件**已满足**，前提是只在「DT 沙盒」工作区、dt-sandbox 仓库内进行。
