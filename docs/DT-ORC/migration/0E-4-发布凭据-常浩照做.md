# 0E-4 最小版：发布凭据放进 dt-gate（常浩照做）

ADR-015 批 0E-4 的最小版：让受信发布 `hermes/scripts/autoloop_publish.py` 能在 dt-gate 账号里为 **dt-sandbox** 真实发布一张单（推本单分支、开 PR）。合并执行器搬家是 0E-4 完整版，不在这里。

命令都由常浩在**主账号终端**里亲手跑。AI 不跑这些命令、不经手令牌；令牌只出现在 GitHub 页面和你的剪贴板里，不要贴进任何聊天窗口。

## 装完是什么样

| | 装之前 | 装之后 |
|---|---|---|
| 发布用的 GitHub 身份 | 没有（真发布关着） | 机器账号 `shanhao1997` 的一把令牌，只在 dt-gate 里 |
| 令牌放哪 | — | `/Users/dt-gate/.dt/publish-github.token`：属 dt-gate、权限 600，主账号、工人、秘书都读不到 |
| gh | 主账号 Homebrew 里的 | `/Library/Application Support/DigitalTwin/bin/gh`：root 所有的副本，只有 root 能换 |
| 代理 | dt-gate 的工具没有代理变量 | `/Library/Application Support/DigitalTwin/gate/publish.json` 写明走本机代理，只有 root 能改 |
| 真发布开关 | 关 | 仍然关；第 7 步由你打开 |

这把令牌能做什么，由 GitHub 一侧挡（11-10 合并隔离实测 12 项）：机器账号只是 dt-sandbox 的协作者（write，非管理员），推不了 main、合并不了 PR，只能推 `claude/**`、`codex/**`、`agent/**` 这几类分支。脚本这边再挡一层：推送目标写死成 `<执行方>/<单号>`。

## 第 1 步：用机器账号生成令牌（浏览器）

1. 浏览器里登录 GitHub 的机器账号 **shanhao1997**（不是你本人的账号；用无痕窗口最不容易登错）。
2. 右上角头像 → Settings → 最下面 Developer settings → Personal access tokens → **Tokens (classic)** → Generate new token (classic)。
3. Note 填 `dt-gate-publish`；Expiration 选 90 days；权限**只勾 `public_repo` 一项**（在 `repo` 这一组里面，别勾整组 `repo`，别的都不勾）。
4. 点 Generate token，点复制。这个页面先别关。

预期：页面显示一串 `ghp_` 开头的令牌。

为什么是机器账号的经典令牌：你本人是仓库管理员，GitHub 的规则集对管理员豁免，你名下的令牌能推 main、能合并；细粒度令牌不能给「别人名下仓库的协作者」用（推断，未实测；第 6 步会核实际拿到的身份和权限）。脚本发现令牌是管理员的会拒发。

## 剩余风险（写明，不在本批解决）

- **没人登录主账号时发不了**：加速器代理 8086 是主账号登录后才有的（0E-2 清单同一条）。那时发布报「没连上」，属于确定没做成，等有人登录后再跑。
- **第 3 步装的那一刻主账号是可信的**：gh 是从主账号的 Homebrew 目录复制的；主账号事先被换过 gh，装进去的就是换过的（和 0E-2 的 stage 同一类）。
- **令牌 90 天到期**：到期后第 6 步的「联网：令牌身份」会不过；从第 1 步重做。到期日记在 GitHub 令牌页面上。
- **令牌的权限比「只推 dt-sandbox 非 main」宽一点**：经典令牌的 `public_repo` 让机器账号能在任何公开仓库开 PR、评论（任何 GitHub 账号本来都能）；写权限只在它是协作者的 dt-sandbox。
- **dt-sandbox 要保持公开**：取 main、查远端分支不带令牌。以后改成私有，这两步要改成带令牌，另做。
- **同账号的边界**：dt-gate 里的其他进程（中台、网关、门卫）和发布脚本是同一个账号，都读得到这份令牌文件；dt-gate 整体是可信控制面（ADR-015 第 3.1 节）。
- 测试用的是替身（本机假 HTTP 远端、假 gh）：真 GitHub 的认证、规则集、代理都没测到，以第 6 步和第一张真实单为准。
