## 3. 需要 ChatGPT 判断的覆盖缺口

`observe` 有两条分支（`twin_scheduler.py` 第 636–651 行）：

- **分支一**：状态库中处于活动状态的 Run → 按单号到台账里找对应的单，调用 `vital_of`，并附上 `heartbeat_age`；
- **分支二**：台账里是 running、但不在库里的单 → 调用 `vital_of`，`run = null`。

10-29 那次观测单在跑单期间，正式库里还没有它的 Run（`DT_STATE_NOTIFY` 关着，靠跑完后的第三次对账才补进去），所以 16 次轮询走的**都是分支二**。两条分支用的是同一个 `vital_of`，进程身份核对的覆盖是一样的。差别只在两处：库内 Run 与台账的关联路径，以及 `heartbeat_age`。D6 写的验收标准是“返回该单且判为 alive、车间与 dispatch 身份都对上；跑完后不再算活动单，库与台账无矛盾”，按字面要求已经满足。
