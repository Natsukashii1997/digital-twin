## 1. 五条原则

1. **以场景为技能的触发入口。** 技能按「什么情况下被叫起来」切分，不为了能力分类拆出一堆独立技能。
2. **以能力模块为复用基础。** 好几个场景都要用的方法集中放一处，场景技能按需去读，避免重复和版本漂移。
3. **以宿主为执行边界。** 猛鬼兽、亚古兽、Claude、Codex、ChatGPT 各有各的上下文，不当成共享一个上下文。
4. **以确定性系统保障可靠。** 技能负责判断；闸门、状态、时机、事实由脚本、中台、定时任务和账本负责（第 2 节）。
5. **以真实工作的反馈驱动进化。** 常浩的纠正、追问、拍板结果和任务失败都已经记在账本里，进化从这些账本读，不另建采集。

## 2. 五条职责分界

| 什么 | 归谁 | 例子 |
|---|---|---|
| 判断 | 技能 | 这件事该续接、催、问常浩，还是收口；拍板请求怎么写 |
| 闸门 | 确定性脚本 / dt-gate | 凭证与派单网关 `autoloop_grants.py`、合并执行器 `merge_act.py`、出口账本 `autoloop_exits.py`、恢复闸 `autoloop_recovery.py`、门卫 |
| 状态 | 中台 agent-autoloop / 对应的事实账本 | 中台的任务与轮次；未闭环账本 `openloop.py` |
| 时机 | 定时任务 / 事件触发 | Hermes 定时任务、卡片按钮插件、中台规则 |
| 事实 | GitHub / 账本 / 外部真实来源 | PR、CI、合并状态；`openloop.py` 的扫描结果 |

**不能放进技能的东西**：授权、幂等、锁、凭证、重复副作用的防护。这些也不能只写在技能自带的 `scripts/` 里，因为模型可以选择不调。闸门必须放在动作真正发生的出口上。技能写了「可以执行」，不等于可以跳过闸门。

## 3. 四种宿主，跨宿主怎么接力

| 标识 | 宿主 | 职责 | 技能装在哪 |
|---|---|---|---|
| H | 猛鬼兽（Hermes 主 profile） | 个人认知、场景判断、组织任务、和常浩交互 | 源文件 `hermes/skills/<名>/`，安装在 `~/.hermes/skills/autonomous-ai-agents/<名>/` |
| A | 亚古兽（Hermes agumon profile） | 企业数字分身的专业能力 | `~/.hermes/profiles/agumon/skills/productivity/<名>/`。和猛鬼兽的技能目录分开，不共用个人记忆（SOUL） |
| W | 工人：Claude Code、Codex、ChatGPT | 开发、验证、独立审查 | 各自宿主自己的技能目录；共享技能的源头是 my-skills |
| S | 确定性系统 | 中台、账本、授权脚本、出口账本、恢复闸 | 不是技能 |

- 猛鬼兽内部的技能在同一个上下文里按需加载，相互之间不需要交接格式。
- **猛鬼兽不能直接调用工人的技能**，只能经中台派单：写好任务单的五要素，工人执行，再收回执。跨宿主的接力是交任务，不是调技能。
- 跨宿主交接只用已有的格式，不另起一套：

| 交接内容 | 用现有的什么 |
|---|---|
| 工作目标和边界 | 任务单五要素：目标、交付物、验收、边界、交给谁（新通道写在 `/Users/Shared/dt-autoloop/tasks/<单号>.md`） |
| 工人执行信息 | 车间回执的 `executor` / `access` / `model` / `chosen_by` |
| 中台任务变化 | 中台的事件记录 |
| 工程审查结果 | 驿窗的问题台账格式 |
| 结果不明 | 出口账本和恢复闸 |

## 4. 两层：场景技能和能力模块

**场景技能**是真正被触发的入口。Hermes 靠 HERMES.md 规程和技能自己的描述来匹配场景，**不另建路由技能**，也不需要每次都把一整串能力加载一遍。

**能力模块**不单独注册成技能，由场景技能按需去读：

| 能力模块 | 哪些场景会用 |
|---|---|
| 五要素任务说明 | 派单、续接、恢复 |
| 拍板请求格式 | 需要常浩决定、异常升级 |
| 授权规则说明 | 派单、卡片回话、合并、外发 |
| 信息边界规则 | 读 Vault、写任务单、日报、卡片 |
| 项目上下文包 | 进度、被追问、续接、收口 |
| 事实核验方法 | 被追问、失败诊断、完成核对 |
| 收口清单 | 交付审查、任务完成、异常关闭 |
| 常浩的偏好与决策依据 | 拍砖、拍板请求、任务规划 |

**能力模块放在哪、怎么读**：
- 放在一个专门的参考库技能里：源文件 `hermes/skills/dt-shared-reference/`，里面只有 `SKILL.md`、`references/<模块>.md`、`CHANGELOG.md`。
- 场景技能按路径去读：`skill_view(name="dt-shared-reference", file_path="references/<模块>.md")`。Hermes 的 skill_view 支持读技能目录里的单个文件，运行记录里有实际调用。不要指望 Hermes 自动跨技能加载 references。
- 参考库**只放通用方法和规范，不放常浩的个人记忆或受限内容**。
- 同一份规范不复制进每个技能。改参考库时，检查所有引用它的技能是否还兼容。
- 亚古兽要用同样的方法时，把方法本身复制进它自己的技能，不共享加载，也不复制个人数据。比如 `thinking-mainline` 的六步诊断法可以提炼后复制进猛鬼兽的拍砖能力。

## 5. 18 个逻辑能力位

逻辑能力位**不等于**独立的技能文件，一个技能可以承担几个能力位。逻辑名只用来表达能力，**现有技能的文件名一律保留**，不做批量改名。「现有资产」只写仓库或安装目录里真有的东西。

状态的意思：已有 = 有完整的技能；部分 = 判断已经有，但散在脚本、提示词、规程或别的技能里；缺 = 没有；脚本 = 应该留在确定性系统里。

- 常浩偏好：出候选，进周一提案卡，常浩确认。
- 技能方法：本地技能按第 6 节自改，共享技能走七站两闸。
- 流程：定时任务、工作流的改动是 D 档，要常浩批准。
- 底层机制：走工程 PR 和审查。

所有进化候选都进现有的周一提案卡（`proposal-digest`），不另建定时任务或提案系统。

### 5b-1 统一五要素任务说明（能力模块，H）

- 把 `workshop` 第 1 节和 `autoloop` 第 2 节两份写法对照，找出一致的、有差异的、遗漏的，以新底座派单链路的最终格式为准合成一份，放进 `dt-shared-reference/references/task-brief.md`。现有四个使用方（`workshop`、`autoloop`，以及引用 `workshop` 第 1 节的 `pdaily-act`、`groupdigest-act`）都改成读它。
- 五要素：目标、交付物、验收、边界（允许做什么、不许做什么、原有约束）、交给谁。另外要求：保留原任务号和上下文出处；不丢历史决定和验收要求；按接收方过滤敏感信息；任务说明写得再全，也不自动带来执行权限。
- 验收：两份写法统一成一份；现有引用方保持兼容，新旧格式都过回归测试；缺任何一个要素时能认出来，并拦下不完整的派单；受限内容进不了工人的任务单；D 档写入单没有有效凭证就不能真正执行。

### 5b-2 拍板请求（能力模块，H）

- 判断流程：在不在常设授权范围内 → 在范围内就照规则办、不打扰常浩 → 不在范围内，判断是不是真的需要他决定 → 整理背景、选项、风险和推荐 → 经现有通道发出 → 记下他的回复，并把决定带回原任务。涉及 D 档写入派单的，仍走「派单 <确认码>」凭证流程。
- 写法：一次最多三问；推荐放第一个；大白话；说清不决定会怎样；选项尽量互斥；不把已经确定的事重新拿来问；不把含糊的回复当成高风险操作的授权；普通对话里的「可以」「继续」不能自动变成 D 档凭证。
- 放在 `dt-shared-reference/references/decision-request.md`。
- 验收：做三类案例——在授权范围内的（自动处理，不打扰）、超出授权的（停下这个动作，发出清楚的请求）、复杂主观取舍的（给推荐和取舍依据，由常浩定）；另测常浩回复后能关联回原任务，并且没有误把授权放大。

### 5b-3 被追问处理（场景技能，H + S）

- 触发：常浩问某件事的进度、结果、原因，或者问为什么一直没下文。
- 处理链：定位原任务和原会话 → 核对账本和真实状态 → 找到断在哪一环 → 分析此前为什么没主动发现 → 下一步在授权范围内就直接做，不在就发拍板或派单请求、等有效授权 → 更新原任务的下一步和下次检查时间（经账本的处置记录入口）→ 记下追问和根因（`openloop_ask.py record`）→ 形成改进候选。
- 自主上限：自动查账、查状态、读会话、核对事实；自动完成已授权的只读动作；可以准备写入派单，但必须等 D 档确认；不能因为常浩问了进度，就当成授权继续改代码或做别的写入。
- 验收：人为制造一项中断的任务，再由常浩主动追问。系统要：找到原任务；找到真实的中断原因；说明此前为什么没主动发现；在允许范围内推进下一步；超出权限时准确请示；更新原任务而不是新建重复任务；留下追问记录和改进依据。**关键看追问之后任务是否真的恢复推进，不看回答得多准确。**

### 5b-4 账本处置（场景技能，H + S）

- 输入是 `openloop.py` 已经扫出来的事项。它不负责扫描、不建第二本账、不另建定时任务，只处理账本里的每一项：

| 账本状态 | Hermes 要做的判断 |
|---|---|
| 在做 | 是否仍有有效进展，下一步是什么 |
| 等你 | 是否真的需要常浩拍板，需要就写成拍板请求 |
| 等外部 | 等的条件是什么，到没到跟进时间 |
| 卡住 | 阻塞原因，恢复方案 |
| 停了 | 该恢复、终止，还是保留 |
| 记录和事实对不上 | 交给事实核对去对账，不能直接改成已完成 |

- **前置工程（台账 D-13）**：`openloop.py` 现在只有 `scan` 和 `show` 两个命令，账本每次扫描都整份重算，没有地方记下 Hermes 的处置（下一步、负责人、下次检查时间、结束条件）。要先给它加一个确定性的处置记录入口（只追加的记录文件，加一个命令），下次扫描时并进对应的行。**技能不能直接改账本。**
- 每条处置要写明：当前事实、阻塞原因、负责人、下一步、下次检查时间、结束条件。
- 自主上限：读取、分析、分类、排序全部账本项；只读核对可以自动做；已授权的动作可以继续；D 档写入必须等确认；状态变化只能经确定性脚本。
- 验收：六类输入全覆盖；每一条都给出明确的处置；没完的事都有下一步或明确的等待条件；不重复建任务；不误报完成；不绕过授权。

### 5b-5 会话续接（场景技能，H 协调，W 执行）

第一批只做下面的通道 a 和 b：

| 通道 | 做法 | 本批 |
|---|---|---|
| a. 中台自己的任务 | 找到原任务号，读中台的状态和事件，核对执行方和最近一次有效结果，认出没做完的步骤，按原授权继续调度，保留原任务和历史 | 做 |
| b. Claude 桌面的历史会话 | 只读原会话，提取目标、约束、已完成和剩下的事，结合项目状态和最新证据，写成续接单，过一遍信息边界，propose 写入派单，等确认后交给有授权的工人 | 做 |
| c. 交给 Claude 桌面里的协调会话 | 协调会话直接接手，Hermes 只负责发现和提醒 | 暂不做，记为已知局限 |

- 通道 b 的读取：Hermes 和 Claude 桌面在同一个 macOS 账号，账本已经在读桌面会话记录（`openloop.py` 借用 my-skills 的 `decision_inbox.py`）。所以读取通道是现成的，要补的是**写给工人的续接单必须先过信息边界过滤**，工人（dt-worker 账号）只能拿到任务单，读不到会话原文。
- **刻意不用的一条路**（台账 D-14）：全局坑 G-24 记过用 `claude -p --resume <会话号>` 在后台续接原会话。它跑在常浩的主账号里、用的是原会话的权限模式，会绕开 dt-worker 的隔离（ADR-015）。不纳入本批；要用必须常浩单独决定。
- 自主上限：通道 a 可以自动读取、对账、续接已授权的任务；通道 b 可以自动读取、整理、写出续接单，写入派单必须等 D 档确认；不让 dt-worker 越权读主账号的会话；不用新建任务的办法绕开原任务的授权和约束；读不到原会话就明确报失败，不凭摘要猜。
- 验收分开做：
  - 通道 a：人为中断一个中台任务；系统找到原任务，恢复原有的上下文和状态，继续执行允许的步骤，不重复产生外部副作用。
  - 通道 b：拿一份真实的 Claude 桌面历史会话；能正确提取原始目标、约束和没做完的事；写出符合五要素的续接单；敏感信息过滤到位；没拿到 D 档凭证不写入；拿到授权后在允许的工人和项目范围内续接。如果这一步没打通，通道 b 只能验收为「具备续接准备能力」，不能说成「桌面会话已经能自动续接」。

### 5b-6 失败诊断（场景技能，H 协调，W 按需辅助）

- 触发：任务失败、超时、没有进展、异常退出、结果不明。
- 分八类，每类处理方式不同：工人异常退出（恢复任务状态和最近一次有效进展）；工具或环境故障（判断环境能不能恢复）；超时没进展；测试失败（取失败证据，写成返修任务）；外部依赖阻塞（确定等待条件和下次检查时间）；授权不足（停下这个动作，转拍板请求）；操作结果不明（交出口账本和恢复闸，冻结可能重复产生副作用的操作）；账本和真实情况对不上。
- 自主上限：可以自主诊断、只读核查、写出恢复方案；自动恢复必须服从现有恢复闸和授权；涉及 D 档写入仍要凭证；技能不能绕过恢复闸，也不能把「准备重试」当成「允许重试」。
- 验收：用八类故障各造测试样本，验证分类正确、诊断有实际证据、恢复建议和故障类型对得上、结果不明的先对账、不重复执行非幂等操作、超出授权范围时正确停下、任务失败不会无声消失。

### 集成验收

从「任务中断 → 账本发现 → 原因诊断 → 任务续接 → 权限确认 → 工人执行 → 结果核验 → 任务收口」完整跑通一遍，由常浩验收。这一批做完之后，再讨论要不要扩大自主执行范围。
