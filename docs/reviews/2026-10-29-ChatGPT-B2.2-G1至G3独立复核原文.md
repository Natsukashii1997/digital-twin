## 三、G4 启动前的必要条件

| 前置事项  | 要求                                                                      |
| ----- | ----------------------------------------------------------------------- |
| 授权    | 单独批准正式库初始化、备份与对账，以及一张用于观测的只读手工单                                         |
| 状态库   | 按 B2.1 接入清单执行 `init → backup → reconcile`，记录初始库版本和历史单导入结果               |
| 数据保护  | 备份、检查 SQLite 版本与文件权限；历史工单数量应按当下实际目录复核，不沿用旧快照的固定数量                       |
| 对账稳定性 | 连续执行对账，第二次不应产生重复 Run 或意外冲突                                              |
| 运行中观测 | 工单处于 `running` 时，`observe` 必须正确返回该单并验证 `alive`，同时核对进程身份                 |
| 结束后观测 | 工单结束后再次观测，确认不再被当作活动车间；状态库与台账没有矛盾                                        |
| 权限边界  | `DT_SCHED_ENABLE`、`DT_STATE_NOTIFY` 保持关闭；不得创建 cron、自动开单、自动确认报告或发送真实取消信号 |

有一处需要明确：G4 名称虽然是“只读观测”，但它的准备阶段涉及正式库的初始化、备份和对账写入。 这些操作必须单独授权，不能用“只读观测”概括为已经获批。

当前正式库不存在，意味着首次初始化可以直接建立 v3 库；如果执行前发现已经存在 v2 库，必须先备份，再允许迁移。

`owner_chat_id` 当前也仍不存在，`DT_STATE_NOTIFY` 未启用。只读观测不必为了它们提前打开飞书身份写入或事件通知能力。
