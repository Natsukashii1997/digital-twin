## 4. 限制与风险

- **脚本层不是硬边界**：模型有 shell，`DT_LARK_CLI`、`PATH`、配置文件都在它能改的范围内；本批挡住的是捏造 / 重放 / 冒用，硬保证要网关签发凭据（协议 2.6，B2.x）。正式授权操作在那之前继续关闭。
- **只证明触发，不证明批准**：同一回合内被注入的指令可借合法消息做别的动作；动作级确认（卡片）留 B2.x。
- **私聊判定依赖 `owner_chat_id`**：bot 回读没有会话类型；配置错了或没配就全拒（宁可拒）。
- **时间只到分钟**：10 分钟时效另留 2 分钟偏差；本机时钟不对会误拒。
- **一条消息一次动作**：常浩一句话里的多个动作要多说几句，或 B2.2 做批量信封。
- **`.env` 开关是否传到工具子进程**只从源码推断，探针 ② 待常浩在飞书里做。
- **合并后到安装前**：`self_check.py` 每天 09:50 会报四个文件缺失或不一致（和 B1 一样，合并与安装一起批即可）。
- 历史台账里 3 个没有 order.json 的目录永远列在 `ignored`；要清理由常浩定。

## 5. 范围外发现（不动）

- `order.sync` 事件挂在单号上，`run.import / run.conflict` 挂在 Run id 上（C3，只记）。
- `progress` 技能把 `need_decision` 当成工单状态（它只在回执里）。
- `dispatch.py run` 同步阻塞且不记 pid，进程被杀后单子会一直 running（B2.2 心跳 / 进程存活）。
- `dispatch.py` 没有锁：`next_no` 与并发检查先读后写。
