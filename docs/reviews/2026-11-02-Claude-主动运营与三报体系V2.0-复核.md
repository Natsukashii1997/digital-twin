## 二、必须改（V2.1 定稿前）

### C1 发送状态和补发队列已经有 G5 在做，不能另起一套（阻断项）

V2.0 §5、§8.1 第 0 批要求“定义统一 `snapshot_id`、成功锚点、幂等键、发送状态与失败补发队列”，§9 还给了一份新的数据契约。

本机现状：B2.2-G5（issue #31，“低噪声报告的可信投递闭环”）已经有一套隔离代码，走完了验收（CURRENT 2026-10-30 条，GO），只是还没合并、没部署：

- `twin_state.py` 的 v4 迁移新增了 `notifications`、`deliveries` 两张表；
- 新增 `twin_notify.py`：同一指纹内容变化记新 revision，只有完整扫描才解决通知；
- 设计是“本地优先、多通道”，飞书只作可选的远程通道；
- 还有分支 `claude/31-g5b-work`、`claude/31-g5c-deliver`（G5-B 终端只读层、G5-C 飞书适配器），进度要现读确认。

这正是三报需要的“本地失败记录 + 恢复补发 + 幂等”。V2.1 要改成：

- 第 0 批的发送与补发**建在 G5 上**：三报是 G5 的第一个真实使用方。先盘点 G5-A/B/C 各分支的 HEAD、测试、审核结论，再决定合并和迁移顺序；
- 不新增第二套投递状态表或补发队列；
- §9 的快照和锚点也要写明存在哪里，优先放 `twin_state`（已有 Event/Ref，加上 G5 的表），不另建文件型账本；
- G5 的正式库迁移（v3 → v4）是单独的闸门（G5 第 0 批的 D1），要在批次表里写成第 0 批的前提。

### C2 批次和正式 cron 的关系自相矛盾

- §8 规定第 1–3 批的退出门槛都是“真实送达 N 个工作日”，这要求先建正式的晚报、早报、周报 cron；但第 4 批又说“统一迁移 cron”，要等 0–3 批验收完才做。两者不能同时成立。
- 改法：
  - **每一批的真实试运行都带自己的正式配置授权**：建这一批的 cron、设投递目标，开发完以后攒成一次请常浩批准；
  - 第 4 批只做收尾：停旧任务、清重复、最后整体回读。

### C3 并跑对象写错了，还会造成台账被写两遍

- §8 第 1 批写“与现有日报按 PRD F2.4 并跑一周”。PRD F2.4 的并跑对象是**云端的日报机器人**，不是本机 07:30 的 Hermes 日报；07:30 那份本身就是 F2.4 的候选替代品。
- 如果晚报开始写 T1 台账，而 07:30 日报还在写同一份台账文档，同一天就会有两份记录。
- 改法：
  - 定一条“**台账只有一个写入方**”：晚报开始写台账的那一天，07:30 日报就停止写入，或者先把晚报写到单独的试运行文档，验收后再切；
  - F2.4 的并跑改为“晚报台账 vs 日报机器人”。

### C4 第 1 批的验收要求周五台账，但写周五台账的周报排在第 3 批

- 第 1 批退出门槛是“5 个适用工作日（包含一个周五代写台账）”，而写周五台账的周报要到第 3 批才做。
- 改法：把“**周五 18:00 只写台账、不推送**”放进第 1 批（和晚报共用取数、发布能力）；第 3 批在这个基础上加周报推送和周度内容。
- 同理，第 2 批早报的“周一本周焦点”要靠第 3 批的周五周报。第 3 批上线前，周一焦点先从现有周一 07:45 周报里取，上线后改为承接周五周报。

### C5 两处事实错误

1. **没有现成的“工作日历配置”**。§1.1 写“法定节假日是否调整沿用现有工作日历配置”。本机核查：Hermes cron 只有 cron 表达式（Blueprint 里也只有 everyday、weekdays 这类预设），Hermes 源码和 digital-twin 的脚本里都没有节假日日历。只按 `1-5` 配置的话，法定节假日照常推送，调休的周末不推送。V2.1 要把这一条改成待常浩定：节假日照常发，或者另外维护一份节假日清单让脚本跳过。
2. **“接收端可见性已验证”做不到自动化**。§4.1 把交付状态分成四档，最后一档是“接收端可见性已验证”。G5 第 0 批审计已经发现：`twin_identity.lark_fetch()` **核实不了 bot 自己发出的消息**（CURRENT 2026-10-30 条）。机器人能拿到的只有发送接口返回的 message_id。所以改成三档（已采集 / 台账已写入并回读 / 发送接口已返回 message_id），“接收端可见”改为常浩抽查。§7.1 用表情回应收集有用率也会碰到同一个限制，要和这一条一起实测。

### C6 PRD 要先同步，否则实施时没有依据

V2.0 §11 说本文不构成修改 PRD 的授权，但 PRD 是这个项目的“唯一真源”，现在 F2.3、F4 仍写着“9:00 晨报、每天主动推送不超过 1 条”。按 V2.0 去组织任务，就和 PRD 冲突。V2.1 在批次表前面加一个“第 −1 步：常浩批准后同步 PRD（新增决定 D20，改 F2.3、F2.4、F4）和 T7 #12 的批次”。
