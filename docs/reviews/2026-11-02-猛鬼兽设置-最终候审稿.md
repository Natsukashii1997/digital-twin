## 一、分工：每样东西放在哪

Hermes 官方的说法：SOUL 是“它是谁”；USER / MEMORY 是它自己用记忆工具维护的“你是谁 / 它学到了什么”；AGENTS.md 或 HERMES.md 是“这个工作区要守的规则”。按这个分：

| 文件 | 放什么 | 谁写 | 什么时候被看到 |
|---|---|---|---|
| `~/.hermes/SOUL.md` | 身份、性格、语气、做事风格、四条底线 | 常浩 | 每次，包括定时任务 |
| `~/.hermes/workspace/HERMES.md`（新增） | 工作规程：信息来源、信息边界细则、动作授权、工程分工、定时与设置 | 常浩 | 工作目录是 workspace 的会话（飞书对话取 `terminal.cwd`，即此目录）；定时任务要设 `--workdir` 才看得到 |
| `memories/USER.md` | 常浩的偏好摘要和指针 | 猛鬼兽自己（记忆工具，上限 1375 字） | 每次 |
| `memories/MEMORY.md` | 环境事实、工具习惯 | 猛鬼兽自己（上限 2200 字） | 每次 |
| 技能（workshop / vault / progress 等） | 具体流程、脚本、参数 | 仓库源文件同步安装 | 用到时加载 |

几个关键约束（已核对源码）：

1. **HERMES.md 只在工作目录本身查找**（`~/.hermes/workspace` 不是 git 仓库，不会往上级找），而且一次只加载一种项目上下文，优先级 `.hermes.md / HERMES.md` → `AGENTS.md` → `CLAUDE.md`。飞书会话的工作目录取 `terminal.cwd`，现在就是 `~/.hermes/workspace`，这个目录目前是空的。
2. **定时任务默认不读项目上下文，只读 SOUL**（`cron/scheduler.py`：`skip_context_files=not bool(workdir)`，注释为“Project context files only with a configured workdir; SOUL.md always”）。所以两件事都要做：把底线留在 SOUL；用到模型的定时任务设 `--workdir ~/.hermes/workspace`。
3. **项目上下文会做注入扫描，命中就整份拦下**；SOUL 属于本人撰写的文件，命中只警告。两份草稿已用 Hermes 自带的扫描规则自测，0 命中（见第六节末）；以后改 HERMES.md 也要复测。
4. **USER.md / MEMORY.md 不手写规则**：它们由猛鬼兽自己增删合并，手写的规则可能被它改掉或挤掉。
5. **速度**：每次请求的固定内容约 71KB（系统提示 29KB、工具定义 41.8KB），现有 SOUL 约 8KB。这次拆分的目的是职责清楚、不重复，不是提速。
