常浩明确选定、定稿、验收过的东西登记在这里（全局规则第 15 节）。以后要改其中任何一项，不论是本来就要改，还是改别处会顺带碰到，都先单独发「改动确认」，等常浩回复再动手；批量授权不算确认。没登记的不等于没定，拿不准按已定处理。

登记写法：新条目写在最上面，写清日期、定了什么（逐条，能对照检查）、定稿文件或提交、基线截图、在哪定的。界面类改动交付前，和这里的基线截图对比。

**定了什么**（细化第 4 版第 2 条里「主线」一项）

1. **页面逻辑**：每条主线是一个大目标，拆成有序的几项，每项下面挂任务单。这一页放当前进度（在做哪项、卡在哪、等谁），不放工作流规则和自动化（归协同页）。
2. **从上到下**：标题行（几条在推进、几条已并入、等你几件）→ 「等你」黑底横条（每件一格：哪条主线哪一项、要你做什么；能点一下办的带按钮，要你亲手做的标「你亲手」）→ 每条主线一段 → 已并入别处的主线折成一行放最下面。
3. **每条主线的头**：名字、编号、哪天起；右边一排进度格（一项一格，完成实心、在做斜线、卡在你这里橙色斜线、挂起虚线）和 X/Y；下一行一句话目标，右边写由猛鬼兽盯、每天 09:00 和 15:00 巡视。
4. **地铁线**：一项一站，从左到右是顺序；已完成的站实心打勾、线是实线，没做到的站空心、线是虚线；在做的站大一圈，卡在你这里的站是橙色；挂起的站虚线圈。站名在下面，有任务单的写「已合并几 / 共几 单」。选中的站外面一圈橙色、站名黑底。
5. **点一站**：线下面接一块，标题行是状态、名字、停了几天、谁负责；一句话现在怎样；任务单按「等你 / 审查中 / 在做 / 没开始 / 已合并」分列，每张写编号、做什么、谁做；最底下一行是猛鬼兽上次巡视对这条主线说的话，卡在你这里的标橙色。默认选中每条主线正在做的那一站。
6. **状态词**：子项沿用 CURRENT.md 主线清单的七种（完成、在做、排队、等你定、先不做、挂起、不做了）；任务单五种（已合并、审查中、在做、等你、没开始）。

## 2026-11-19 · 工作台协同页

- **在哪定的**：Claude 会话（数字分身工作台｜协同页选稿与其余五页），常浩 11-19 三轮：第一轮三版「都不满意，没有明确这一页的逻辑」，说清协同页只讲规则、工作流在工作台里拖拽重组、自动化只收集呈现；第二轮「自动化用甲，工作流用丙的甬道…自动化和这个工作流都不需要有任何的解释说明的文字」；第三轮（泳道和规则怎么接）「选甲」；issue #237。
- **定稿文件**：[docs/design/workbench.html](design/workbench.html)（侧栏「协同」可点）；选稿预览 https://claude.ai/artifact/7qLDigGDupeBkAmwNmHexC （第三轮，版本号 `1795095271-4489`）。工作流是示例数据；自动化是 11-19 从猛鬼兽、亚古兽、Codex、Claude Code 和本机定时任务实际盘出来的。
- **基线截图**：`~/Library/Application Support/DigitalTwin/evidence/2026-11-19-workbench-collab/`
  - `workbench-collab-1440.png`：协同页 1440×900 首屏
  - `workbench-collab-fullpage-1440.png`：整页（截图时临时放开了外壳的固定高度）

**定了什么**（细化第 4 版第 2 条里「协同」一项；两者的定义不变）

1. **只讲规则**：不放当前运行状态（停在哪的单、卡在哪、最近几次、上次下次）。这些归首页和记录页。
2. **不放解释说明的文字**：没有页头说明、定义、操作提示、「收自 / 要改找谁」。
3. **从上到下**：工作流（标题行带条数）→ 所有工作流都守的五条 → 工作流页签（名字、步数、版本 / 草稿，改过的标「改了」，最后是「+ 新建」）→ 这条工作流的名字、版本、一句目标，右边三格（什么时候开始、整条怎样算做完、上限）→ 模块条 → 泳道 → 自动化。
4. **泳道**：一家一条道，顺序是 我、猛鬼兽、亚古兽、Claude Code、Codex、GPT；「我」那条道是橙色底。一列一步，块上写这一步叫什么、交出什么，块和块之间用折线连起来。列头有往前、往后、删除；最右是一列斜线格，放进去就加在最后。
5. **规则接在泳道下面（第三轮甲）**：同一张表的下半，每一列正下方四行：做什么、用什么（写明是第几步交出的什么）、怎样算过、不过怎么办（写明退回第几步）。全部摊开，不用点；拖一块，规则跟着那一列走。
6. **怎么改**：鼠标按住块拖，横着改先后、竖着换一家做；模块条上的模块拖进任意一格就加一步。要你点头的步骤不能拖给 AI，AI 的活不能拖进「我」那条道，拦下时在泳道下面说原因。
7. **改了不马上生效**：改过之后，模块条右端出现「✓ 改了，检查通过」或「✕ N 处对不上」，下面出现黑底的「改了，还没生效」：原来和现在两条顺序对照、四项检查（要用的东西前面有人交出、不过时退得回去、审的和做的不是同一家、合并排在所有改动之后）、「送去等我拍板」（有对不上的就不能点）、「撤销改动」。对不上的那一步在块和规则上标红。确认后成为新版本，在跑的单按旧版本跑完。
8. **自动化**：按负责人分组（猛鬼兽、亚古兽、Codex、Claude Code、本机），组头黑底写个数和在跑几个；每个一行：名字和一句做什么、什么时候跑、在跑 / 已暂停（暂停的写一句缘由）。只登记，不在这里建，没有暂停按钮。

**还没定的**：新建工作流的完整流程、改判定标准文字、换人的下拉；首页「9 个自动化」和侧栏「协同 6 · 9」的数字要不要按协同页的 21 个改（改首页已定内容，另行确认）；「优化线索」放不放、放哪。

## 2026-11-19 · 猛鬼兽个人项目日报卡片（乙版）

- **在哪定的**：Claude 会话（猛鬼兽日报｜版式重构与回复派单）。常浩 11-19 先提意见（形式大于使用价值、没有行动指引），看了发到私聊的三版真卡片预览后回「选乙」，对实施计划回「都按推荐」；issue #226。它取代 2026-11-10 的甲版定稿（五板块全放卡片、不折叠）。
- **定稿文件**：拼卡片的代码 `hermes/scripts/pdaily_publish.py` 的 `build_card`；样例 [hermes/samples/pdaily-card-b-2026-11-18.json](../hermes/samples/pdaily-card-b-2026-11-18.json)（11-18 的真实数据经模型写稿后的产物）；规格 [个人项目日报-V2-设计.md](个人项目日报-V2-设计.md) 4.0。
- **基线**：三张预览卡片的 JSON 和发送回执在 `~/Library/Application Support/DigitalTwin/evidence/pdaily-redesign/`（`preview-b.card.json` 是选中的一版；预览里的按钮是摆样子的）。飞书卡片在客户端里渲染，没有网页截图。

**定了什么**

1. **总规矩**：一件事只出现一次，按「接下来归谁」摆。风险写「是什么问题」，拍板写「你要定什么」，两边用编号互相指。
2. **四板块，顺序固定**：核心数据速览 → 昨日关键成果 → 风险与阻塞 → 需要你拍板。没有「今日推进」，没有单列的「工程自检」。
3. **核心数据速览**：四行（有推进的项目、合并 PR、需要你拍板、风险与阻塞），不再有「Hermes 代理动作」一行；列宽 25% / 15% / 60% 沿用 11-10 定稿。
4. **风险与阻塞**：按原因归类，一类一行，三列（问题、涉及、去向，30% / 45% / 25%），用白话，不用「运行风险 / 管理失真 / 协作阻塞」。每类必须有去向。每类涉及哪些项目和编号放在表下默认收起的折叠面板里。
5. **去向**：现在只有「→ 拍板 N」和「只观察」两种。「猛鬼兽自己处理」要等第 3 批有了执行机制才出现。第 3 批（#236）加上了第三种「猛鬼兽派只读单查，明天报」：只给不用常浩定的风险，每天最多 2 类，日报发出后在后台开只读单。
6. **工程自检**：正常时页脚一句；有问题时是风险表的最后一行，原文进折叠面板。
7. **需要你拍板**：一张表，四列（#、事项、推荐、已挂，8% / 34% / 43% / 15%），编号 ①②③；每条都有明确推荐；缺材料的事不进拍板；已挂几天由脚本算。
8. **怎么回**：第 1 批靠引用卡片回一句（「① 按推荐」）。第 2 批在表下加一排按钮（`全部按推荐`、`① 按推荐`…），不做、先放着仍靠引用回复；卡片里不放文字输入框（Hermes 的飞书接入不传输入框的内容）。
9. **完整报告**：和卡片同一套逻辑、同一顺序，六段加覆盖与可信度，没有「今日推进计划」。

**还没定、别当成已定的**：点击后的回执文案。

2. **从上到下的顺序**：报告页签（每次托管、每晚一份）→ 六个数字 → 一夜时间轴 → 等我拍板 → 昨晚的经过 → 花了多少额度。
3. **六个数字**：派了单、提交 PR、完成合并、秘书替你定、等你处理（橙色）、工人用时。
4. **一夜时间轴**：横轴是托管时段；每单一行，分「在做」（按执行方上色）、「审查」（斜线）、「等你」（橙色虚线框）；下面两行是「秘书替你定」和「完成的动作」的时刻；带图例。
5. **等我拍板**：黑底横条、四张一排、每张六层，和第 4 版一样；来自这次托管的卡排在前面。
6. **昨晚的经过**（版式甲）：
   - 一件事一件事往下说。每件一个标题行：序号、白话标题、状态、执行方和单号、用时。标题用白话，不用工程里的叫法。
   - 每件四段，左边小标签：这件事（是什么、为什么做）、经过、现在的结果。第四段「要你做」在右边单独一栏：要动的是橙色、带按钮（跳到上面对应的拍板卡），不用动的写「不用做什么」；栏里附三行事实（PR、改动、用时）。
   - 句子里三种标记：橙底加橙线是秘书替我定的，后面跟「推翻」；橙色虚线是没定、留给我的，后面跟「去定」；黑色下划线是做完的动作（推了哪个分支、开了哪个 PR）。
   - 不要开头的总述；不要单独的「决定梳理」板块；不单列「撤不回的动作」，做完的动作直接写在经过里。
7. **花了多少额度**：最后一条横条，只算 Claude Code 和 Codex 在这次托管期间用掉的本周额度（托管前 → 托管后）；GPT 网页取不到，不计。
8. **示例数据**：等我拍板从 4 条变成 6 条（多了来自 11-18 夜间的两张），首页的清单行、刊头数字跟着变成 6。

**实现时要补的**（设计稿里没有，常浩已知）：白话由猛鬼兽写，是新的 AI 功能，上线时登记进 AI 接入，写完由脚本核对数字；额度差值要在托管开始和结束各记一次读数，现在没有这个记录点。

2. **各入口放什么**：

   - 分身：秘书、托管的模式和设置，加原「授权规则」（授权规则也是给分身的规则）。
   - 记录：原「运行记录」。沉淀：提案、坑、已定内容。
3. **等我拍板两处都有，形式不同**：

- **基线截图**：`~/Library/Application Support/DigitalTwin/evidence/2026-11-19-workbench-home-v3/`
  - `workbench-home-v3-1440.png`：1440 宽首屏

**定了什么**

1. **外壳**：左侧栏（首页、等我拍板、工作流、自动化；设置组：执行方、授权规则、托管 · 秘书、运行记录；底部五个执行方状态灯）加右侧主区滚动。工作台用应用窗口的大小铺满，不做成一张长网页。
2. **视觉**：字体 Berkeley Mono（本机没装时用 JetBrains Mono），中文回落系统中文字体；浅灰点阵底、细黑线、等距插画、黑底反白块；橙色只给「我」和需要注意的东西，状态色另用绿 / 琥珀。
3. **首屏刊头**（照常浩 11-19 给的参考图）：黑底标签「N 件事等我拍板 ✦」；大标题「数字分身 工作台」；一句说明加三条 ↗ 要点；左下角执行方小规格表；右边等距系统图：黑色平台「AGENTS · 执行方」上放五个 AI 方块和浮起的橙色「我」，「我」带标注线写「N 件 · 等我拍板」，平台下层是虚线的授权规则层，定时、飞书消息、新 PR 三个触发从三边接入；底部「WORKBENCH」点阵字、「+ 新建工作流」大按钮（斜线阴影）、右下角 ↓ 跳到拍板区。
4. **等我拍板**：黑底横条，卡片四张一排；每张固定六层（类型和档位、标题限两行、提问限三行、三行详情、来源、按钮），卡片等高，按钮在同一水平线。工作台里的改动（新建 / 修改工作流、改规则）用橙边卡片，按钮是「确认生效」。
5. **工作流的定义**：多个 AI 协作完成一件事。角色只有六个：Claude Code、Codex、GPT（ChatGPT 网页）、猛鬼兽、亚古兽、我；脚本是配套，不算一步。每条工作流画成一排等距角色方块（CC 黑、CX 灰、GPT 斜线、猛鬼兽白、亚古兽浅灰、我橙），从左到右是顺序，标出进行中的单子停在哪一步；还没生效的草稿画虚线。
6. **自动化和工作流分开放**：脚本按时或按事件跑、最多一个 AI 参与的（日报、热点榜、合并官等）叫自动化，不算工作流。
7. **层级**：刊头 → 等我拍板 → 主栏工作流 + 右侧窄栏（今日运行：四个大数字、小时间轴、「需要留意」「接下来」各两条；托管 · 秘书：两行四态开关；自动化：紧凑清单）。执行方不单独做大卡片，放进系统图、小规格表和侧栏状态灯。
8. **改动生效方式**：在工作台新建或修改工作流、改规则，保存后先进「等我拍板」，常浩确认后才生效。

**过程**：11-19 第 1 版出了三版（双栏控制台 / 流水线 / 刊头长卷），常浩挑了各版满意的部分；第 2 版综合时把每块做成一样大、一样重，还丢了参考图的刊头，被否；第 3 版定稿。这次的教训写进了 ui-styles 的「版面层级」规则。
