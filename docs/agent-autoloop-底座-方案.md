## 2. 总体架构

### 2.1 七层

```
 ① 入口（常浩）     飞书私聊（猛鬼兽）     驿窗侧栏（看 + 点）     命令行 / MCP
        │                   │                      │
 ② 前台大脑        Hermes 猛鬼兽：对话、记忆、Vault、人设、白话汇报
                    私聊 ──► 派单事件      按钮点击 ──► 卡片回答
        │
 ③ 中台（fork 版 agent-autoloop，本机常驻）
      事件 → 规则 → 一轮 → 回执；卡片挂起不占进程；定时；事件溯源日志
      + 授权分档（第 5 节）  + 主线（第 6.6 节）  + 花费闸
        │
 ④ 车间            Claude Code / Codex 官方命令行（每个事项一个 worktree）
                    审查员：驿窗 ChatGPT High（经接力审核门）
        │
 ⑤ 副作用出口      固定脚本做所有对外动作：推分支、开 PR、合并、发飞书
                    幂等键 + 结果不明就冻结对账 + 回读核实（第 5.3 节）
        │
 ⑥ 交付与知识      GitHub（issue / PR / CI）   Vault   决定记录   LESSONS   my-skills
        │
 ⑦ 观测            驿窗看板（读中台事件流）   工程自检   个人项目日报
```

### 2.2 一句话分工

**常浩定目标和权限、回答卡片、说「合并」；猛鬼兽懂常浩、把话变成事件、把卡片变成白话；中台管排队、派活、挂起、定时和账；Claude / Codex 只在 worktree 里干活；所有对外动作走固定脚本；GitHub 存交付，Vault 存长期知识；驿窗是看板和第二个拍板入口。**

| 角色 | 负责 | 不负责 |
|---|---|---|
| 常浩 | 目标、授权档位、回答卡片、说「合并」 | — |
| 猛鬼兽（Hermes） | 对话、记忆、Vault；私聊转派单事件；卡片的飞书收发；状态白话汇报 | 不自己调 CLI、不替常浩回答卡片（托管暂停） |
| 中台（fork） | 事件、规则、派活、并发、挂起续接、定时、花费统计、事件溯源 | 不懂常浩、不存人格记忆；不直接对外发东西（交给副作用出口） |
| Claude Code / Codex | 在 worktree 里改代码、写文档、提交到本地分支，回执里交结论 / 提问 / 复查 | 不推 main、不合并、不联网做副作用 |
| 副作用出口（固定脚本） | 推本单分支、开 PR、按常浩点击合并、发飞书 | 不做判断，只做核对过的固定动作 |
| 驿窗 | 看板、侧栏拍板、ChatGPT 审查员 | 不调度、不开网络端口 |

## 3. fork 策略：怎么自己开发又不被上游拖垮

### 3.1 上游的事实（2026-11-15 只读查）

- 上游 11-03 建仓，到今天 22 个版本（v1.0.0 → v1.8.5），近期几乎一天一版；维护者一人占大头；5379 星、985 个 fork；MIT。
- 内核小而硬：kernel 约 2000 行、protocol 约 770 行、worker 约 1000 行；测试 97 个文件、约 1.9 万行，含 2 万步随机模拟和强杀测试。
- 核心目录在 v1.6.0 → v1.8.5 改了 922 行。**改了 `kernel/decide.ts`、`protocol/rules.ts` 的 fork，几乎每周都要解冲突；只加插件的 fork 同步成本低。**

### 3.2 四层分法

| 层 | 放什么 | 改不改 | 同步上游 |
|---|---|---|---|
| L0 上游内核 | kernel、protocol、worker、host、cli、sim | **原则上不改**；非改不可的写进 `PATCHES.md`，每条能单独撤 | 每周跟一次上游 Release（先跑全量测试 + 模拟） |
| L1 自己的插件 | `plugins/dt-*`：飞书只发通道、驿窗通道、worktree 版 Claude / Codex、Hermes 来源 | 随便改 | 不受影响 |
| L2 极少的内核补丁 | 只有一处：规则加 `tier`（授权档）字段并透传到一轮的任务里（第 5.2 节） | 改，尽量做成通用能力**提 PR 回上游** | 合回上游后补丁消失 |
| L3 个人配置 | 规则、Skill、授权表、名册生成器、副作用脚本 | 放 **digital-twin 仓库**，不进 fork | 不涉及 |

### 3.3 仓库形态

- **GitHub 上点 Fork 得到的仓库只能是公开的**。所以推荐：建一个**私有仓库**，用 `git clone --mirror` 推上去，再加 `upstream` 指向上游；个人配置、密钥一律不进这个仓库。
- 名字建议 `Natsukashii1997/agent-autoloop`（保留上游名，方便对照），名册里登记为新项目，`type: product`。
- 本机从安装版切到 fork 版：卸载当前安装（保留数据），按上游「本地仓库安装」的写法用 fork 目录装（`AGENT_AUTOLOOP_REPO=<fork 目录> sh install.sh`），之后 `update` 跟 fork 走，不再跟上游 Release。

## 5. 授权与安全：从「写进提示词」变成「真的拦得住」

### 5.1 现状差距

中台自带的「先问清单」（删数据、停服、花钱、对外发消息……）只是写进提示词的话，Agent 不照做中台拦不住；`access` 只有 read / edit / full 三档，隔离靠各家 CLI 自己（agent-autoloop SECURITY.md、`protocol/rules.ts:15`）。

### 5.2 三道拦截

1. **规则档位**（L2 补丁）：每条规则加 `tier: A|B|C|D`，对应常设授权四档。中台把它透传进一轮的任务；`agent-autoloop check` 拒绝「`full` 权限配 D 档」这类组合。这是唯一的内核改动，做成通用的「规则自定义元数据透传」提 PR 回上游。
2. **工具层拦截**：worktree 版 Claude / Codex 插件按档位生成权限配置（复用 agent-kit 的 guard-git、bash-precheck 和权限文件）：任何档位都不许推 main、不许 force push、不许读密钥目录；A 档才免确认改文件；`full` 不开。
3. **副作用只走出口**：Agent 想推分支、开 PR、发飞书、合并，只能在回执里发事件，由固定脚本执行（5.3）。Agent 本身没有联网做副作用的权限。

另外两条硬规矩：卡片的 `answerers` 只填常浩一人；中台的 MCP 不配进 Claude / Codex 的用户级配置（否则一轮能自己回答自己的卡片）。

### 5.3 副作用出口（融合账本、调度恢复、合并的精华）

所有对外动作统一由 digital-twin 里的固定脚本执行，作为中台的 `command` 规则（不受 `access` 约束，所以脚本本身要严）：

| 动作 | 档位 | 关键核对 |
|---|---|---|
| 推本单分支 | A | 只推 `claude/` `codex/` 前缀分支；不碰 main |
| 开 PR | A | 一单一个 PR；关联 issue；PR 描述带中台轮次号 |
| 发飞书私聊 | A | 只发常浩私聊；受限内容拦下；同一卡片号只发一次，回读核实才算送达 |
| 合并 | B（常浩点卡片） | 复用 merge_act：HEAD 一致、CI 通过、干净副本跑测试、L3 不走飞书、`--match-head-commit` |

共用的账本规则（来自 custody_ledger 和 twin_scheduler）：

- 每个动作一个幂等键（`<动作>:<仓库>:<对象>:<版本>`），同一个键只执行一次；
- 执行结果不明（超时、断网）→ 记「结果不明」并**冻结同一对象的后续动作**，先只读查远端对账，凭证据记成已做或未做，绝不盲重试；
- 撤不回的动作（合并、对外发消息）必须有常浩点击；
- 账本复用中台的事件日志（回执里的事件即记录），不另建数据库。

## 6. 关键链路

### 6.1 派活：私聊一句话 → 一个 PR

1. 常浩私聊：「让 Claude 给 dt-sandbox 加个 xx」。
2. 猛鬼兽（新技能 `autoloop`，替代 `workshop`）整理五要素（项目、目标、验收标准、边界、交给谁），项目必须在名册里；按常设授权判断写入单要不要先确认（PRD F5.3）。
3. 猛鬼兽用 `hermes` 来源密钥 `POST /v1/events`：`type: dispatch.<项目>.write|read`，`subject: <项目>#<issue>`，`detail` 写五要素。只有 twin_identity 核实过的常浩私聊才会触发。
4. 中台按规则派：规则由 `autoloop_rules.py` 从名册生成（每个活跃项目一条，写入类只给 `write_allowed: true` 的），目录、Agent、权限、档位只由规则决定，事件改不了；名册外的项目没有规则，派不出去。
5. worktree 版 Agent 插件按 `subject` 建或复用 `~/.hermes/worktrees/<项目>/<issue>`、分支 `claude/<issue>-<短名>`，开跑前查执行方可用（不能用就报错、不换家）。同一仓库同一时间一单（`maxActive: 1`），总并发 2。
6. Agent 提交到本地分支，回执发 `push.request` 事件 → 副作用出口推分支、开 PR → 每轮完成通知（结论 + PR 链接 + 轮次号）经飞书通道到私聊。

〔待实测〕派单正文在中台里属于「资料」不是指令：`dt-dispatch` Skill 要写明这条信任只给 `hermes` 来源，正文引用的外部文字仍只当资料。

### 6.2 拍板：卡片 → 飞书 / 驿窗 → 回中台

- `dt-feishu` 通道：复制内置飞书通道、**去掉监听**（`plugins/feishu/channel.ts:208-229` 那段），以猛鬼兽机器人身份只发不收；卡片 `ref` 有值时更新原消息（回答后改成「已选：xx」）。
- 点击由猛鬼兽网关收 → `merge-buttons` 新分支 → `autoloop_answer.py` 用通道密钥 `POST /v1/cards/<号>/answer {choice, by: 常浩 open_id, ref: 原消息号}`；中台核对回答人和原消息，只认第一次。
- 打字也能答：引用卡片回「选 2」或一句想法。
- 驿窗侧栏（批 6）：`dt-postpane` 通道写文件收件箱，驿窗显示、写回答案，通道转交中台。飞书和驿窗谁先答算谁（中台只认第一次回答），另一边更新成「已在 xx 回答」〔待实测：多个通道各自的消息号怎么记、能不能都更新〕。
- 桌面通知保留作兜底。

### 6.3 交付：审查 → 常浩点合并

用中台的交付插件，但**停在审查**（`deliver-review`），不让它自己合并：

1. 审查：交付插件的 `review.command` 接两种审查员：合并官规则（快速判定）、驿窗 ChatGPT High（L2–L3 按 MA-02 审几轮，最多 5 轮）。
2. 通过后发「合并」卡片；常浩点了，副作用出口按 5.3 合并；退回就在 PR 留言、派返修一轮。
3. 合并官一致率继续记，作为以后放宽档位的依据（同类 ≥20 次、≥90% 才讨论）。

### 6.4 定时与报告

新的定时活写成中台规则（`cron`）。报告类统一用 pdaily 模式：`command` 规则出事实快照 → Agent 写 → 脚本核对 → 不过就降级成事实版，取不到写「未知」不当 0。现有 Hermes 定时任务批 7 再逐个迁。

### 6.5 夜间行动提案（旗舰用法）

1. 每天 22:30 规则让 Agent 读名册、主线、open issue，提出「今晚可替你推进的 3 件事」，发多选卡片。
2. 常浩勾选 = 当晚授权（只限卡片列出的项目和动作，档位不超过 B）。
3. 夜里中台按勾选派单，只做到开 PR；遇到拿不准的挂起等早上。
4. 次日个人项目日报汇报：做了什么、PR、挂起了什么。

这条接住了原来「Multica 夜跑」和一部分「托管」想要的效果，但不需要替常浩拍板。

### 6.6 主线负责人

- 主线 = 一个目标 + 有序的子项（沿用 CURRENT.md「主线清单」的七种状态），存 digital-twin `mainlines/<名>.json`（和 CURRENT 同步）。
- 每完成一轮，回执发 `mainline.progress` 事件；主线规则检查：下一项能开就派（档位内）或发卡片问；
- 每天巡视规则：某条主线超过 N 天没进展、或同一阻塞连续出现，发卡片提醒，并进日报。
- 这就是常浩 11-14 要的「盯住多单大任务防丢防停」，和托管（替拍板）分开，可以先做。

## 7. 和 PRD、架构基线的关系

- **PRD 要改的地方**（常浩已定方向，写 ADR 时一并修订）：F4.3（定时改由中台规则，不再是 Hermes cron）、F5.4（执行改由中台 + worktree 插件，不再是 Hermes 调 CLI）、F5.6（卡住时由中台卡片挂起）、F9（巡检加中台）、第 3 节终局图。原则 1「一个入口」、第 8 节信息边界**不变**。
- **ARCHITECTURE**：Multica 退出执行层（ADR-013 被 ADR-015 部分取代）；ADR-014 托管标为「暂停」；V6.0。
- **AI 接入（P-13）**：fork 版中台是 product 项目，没有图形界面，用配置文件 + `doctor` 自检命令；`ai_access.json` 加功能 `autoloop-dispatch`（执行方 claude / codex，接入方式「本机 CLI（经中台）」）。

## 10. 回退

- 批 1–7 期间旧结构不删：回退 = `agent-autoloop pause <规则>` 或卸载中台（保留数据）；merge-buttons 新分支只认中台卡片的按钮，删掉不影响原有按钮。

- 批 8 之前不删任何旧东西；Hermes 定时任务迁一个、验一个、删一个。

## 11. 风险

| 风险 | 对策 |
|---|---|
| 上游一天一版，fork 分叉越来越大 | 内核只留一处补丁并争取合回上游；每周同步一次；插件层不受影响 |
| fork 公开导致个人配置泄露 | 用私有镜像仓库；个人配置在 digital-twin，不进 fork |
| 派单正文被当资料，Agent 不照做或做偏 | `dt-dispatch` Skill 写清信任边界；批 2 用 5 单验收 |
| 「先问清单」拦不住 | 三道拦截：档位、工具层权限、副作用只走出口 |
| 中台「至少一次」语义导致重复副作用 | 出口幂等键 + 结果不明冻结对账 |
| 续接长会话越来越贵 | 主线用「新会话 + 读主线文件」而不是无限续接；`later` 只用于短会话 |
| 单机中台挂了 | launchd 常驻自动拉起；工程自检查 `/healthz`；事件日志强杀不丢 |
| 两套结构并跑打架 | 并跑期间名册加 `dispatcher: autoloop|legacy`，一个项目只归一边；旧结构本来已闲置 |

## 12. 要常浩拍板的事

1. **fork 形式**：推荐**私有镜像仓库 + upstream 远端**（GitHub 的 Fork 只能公开）；备选：公开 fork，个人配置严格放 digital-twin。
2. **改内核的尺度**：推荐**插件优先，内核只加一处 `tier` 透传并提 PR 回上游**；备选：放开改内核，接受每周解冲突。
3. **驿窗接中台**（改驿窗「第三方只做一键唤起」的定位，属已定内容）：推荐**改**，驿窗作为中台的看板和第二拍板入口，不开端口、不改定过的外观交互；备选：驿窗不接，只用飞书。这一条按 P-14 另发「改动确认」。
4. **送审**：按 ARCHITECTURE §12.4，推荐常浩看完、改完后经驿窗送 ChatGPT High 审查，再写 ADR-015。
